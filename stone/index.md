# Architecture

- [Carvestone](arch/carvestone.md) - Planning and knowledge store for humans and AI agents, with the CLI stone.
- [Stone binary](arch/carvestone/stone.md) - The one executable: CLI, local web server and MCP server over a shared engine.
- [carvestone-cli](arch/carvestone/stone/cli.md) - The stone binary; it parses arguments and renders results.
- [carvestone-core](arch/carvestone/stone/core.md) - Item model, ids, relations, provenance and body sections.
- [carvestone-engine](arch/carvestone/stone/engine.md) - Every operation on a repo; the CLI and later adapters only parse and render.
- [carvestone-git](arch/carvestone/stone/git.md) - Carvestone's git wrapper: shells out to the git CLI and parses its output, with no SQLite and no writes to the repository.
- [carvestone-graph](arch/carvestone/stone/graph.md) - Parses source files with tree-sitter into symbol and reference facts and resolves them into a code graph.
- [carvestone-mcp](arch/carvestone/stone/mcp.md) - The optional read-only MCP stdio server behind `stone mcp`, for agent clients without a shell.
- [carvestone-index](arch/carvestone/stone/search-index.md) - Derived SQLite index with full-text search (milestone M-2).
- [carvestone-server](arch/carvestone/stone/server.md) - The HTTP server behind stone serve; it exposes engine reads and writes as a JSON API with an event stream and the embedded web UI.
- [carvestone-store](arch/carvestone/stone/store.md) - Frontmatter reader and line-patch writer, the stone/ layout, the write lock and id allocation.
- [Web UI](arch/carvestone/web-ui.md) - The browser app that stone serve embeds and serves.
- [carvestone-web](arch/carvestone/web-ui/web.md) - The browser UI served by stone serve: docs, items, board, architecture, code and timeline views over the server API.

# Decisions

- [ADR-1: Files in git are the truth; the SQLite index is disposable](decisions/ADR-1.md) - Plans, docs and architecture must diff, merge and review like code, and stay usable without Carvestone.
- [ADR-2: Rust single binary with an embedded React UI](decisions/ADR-2.md) - One download, offline, no runtime. The UI needs a board, a map and an editor.
- [ADR-3: Own schema as an OKF v0.2 profile](decisions/ADR-3.md) - We need our own fields (relations, task sections, architecture) without locking the data into one tool. OKF v0.2 requires only type, allows extra keys, and defines provenance and freshness.
- [ADR-4: Filename is the id; numbered files never move](decisions/ADR-4.md) - Backlog.md puts the title in the filename and moves files to completed/, which breaks paths and links. OKF uses the path as the concept id.
- [ADR-5: Restricted YAML frontmatter with a line-patch writer](decisions/ADR-5.md) - CLI, UI and agents all edit items, and every edit must be a minimal diff.
- [ADR-6: Git links come from trailers and the working diff, not hand-kept lists](decisions/ADR-6.md) - Groma.md asks agents to log each modified file on the Backlog.md task by hand. That is easy to forget and goes stale.
- [ADR-7: Search returns sections, ranked by BM25 plus links, under a token budget](decisions/ADR-7.md) - Agents pay for every token. Whole-file results waste context, and similarity alone isn't deterministic.
- [ADR-8: Architecture in our own agent-first format, backed by the code graph](decisions/ADR-8.md) - Groma.md keeps relations in markdown tables and nests ids under a groma: key. That is fine for its map, but costly for agents to read and edit. A separate code graph (graphify) knows the real dependencies but nothing…
- [ADR-9: Replace Backlog.md, Groma.md, graphify and fumadocs; keep Docs MCP](decisions/ADR-9.md) - Separate tools mean separate indexes, and none of them can link to the others.
- [ADR-10: One engine crate behind every adapter](decisions/ADR-10.md) - The CLI, MCP and HTTP must behave the same.
- [ADR-11: Code graph from tree-sitter, derived and kept out of git](decisions/ADR-11.md) - Agents need code structure (definitions, callers, dependencies, modules, impact) cheaply and up to date. Full compiler or LSP resolution per language is heavy; name matching alone is often wrong.
- [ADR-12: Precedent lookup ranks finished tasks by component and change shape](decisions/ADR-12.md) - Agents on Freightline copy the pattern of a similar finished task before planning. Today only word search exists (CS-111).
- [ADR-13: HLD and LLD are views of the architecture, not new item types](decisions/ADR-13.md) - Stone draws C4 diagrams (context, container, component, dynamic), keeps architecture items (system, container, component) and, with M-12, opens a service from the diagram into modules, entry points and classes. Nothing…
- [ADR-14: Web UI: four spaces, state on every item, owner actions only](decisions/ADR-14.md) - Backlog.md and Groma.md show state on each item. The Stone web UI made people read pages to learn the same facts. The 2026-11-04 release removed all editing while the PRD still promised it.
- [ADR-15: Rewrite the Rust tests as feature tests](decisions/ADR-15.md) - Replace the Rust test suite with feature tests, in one cutover. The owner chose this after the mutant baseline showed the import tests caught 390 of 434 viable mutants, and 1,194 tests was more than the product needs.
- [ADR-16: First public release keeps four linked parts and cuts migration and inferred patterns](decisions/ADR-16.md) - Carvestone goes public on GitHub. The owner wants a sharp tool with a clear definition. The PRD lists five parts and replaces four tools. Separate tools cannot link a task to a symbol or a commit to a decision.

- [ADR-18: The architecture UI is two C4 diagrams, system architecture and solution architecture](decisions/ADR-18.md) - The owner cannot read the architecture UI. It mixes a system map, a domain view, a low-level view and service pages. A stranger must learn what the parts are and how they talk within 60 seconds. The owner named the C4…
- [ADR-19: Publish from a fresh history with client names removed, under MIT OR Apache-2.0](decisions/ADR-19.md) - The repo has no remote and 73 commits. 80 tracked files name Freightline or Fleetwise, mostly in stone/, and 3 of them are in crates/ or web/. The repo root has no LICENSE file, and README.md is empty.

The two can disagree. Fleetwise's run-time connections are mostly in mermaid docs. The owner wants…
