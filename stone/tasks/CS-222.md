## Description

The finish guide tells agents to run `stone edit <id> --check-ac 1 --check-ac 2`, and clap answers `the argument '--check-ac <CHECK_AC>' cannot be used multiple times` (exit 2). The M-18 baseline counts 21 failed calls of this kind. After this task the CLI accepts the repeat and ticks every named box in one locked write, so the guide is right as written.

## Plan

Outside types: `crates/engine/src/edit.rs#Edit`, `crates/engine/src/api.rs#PatchRequest`, `crates/core/src/section.rs#check_box`.

1. Seam A: `crates/engine/src/edit.rs#Repo::edit_if_match`. It catches: several boxes ticked in one write, and a wrong number that must leave the file alone. It misses: the clap wiring. Test choice: patch `crates/engine/tests/features/tasks.rs#ticking_a_criterion_changes_only_that_box`.

In `Repo::edit_if_match` replace `req.check_ac.is_none()` with `req.check_ac.is_empty()`, and replace `if let Some(n) = req.check_ac` with `if let Some(&n) = req.check_ac.first()` (the stub ticks the first number only). In `crates/cli/src/main.rs#run`, arm `Command::Edit`, write `check_ac: args.check_ac.into_iter().collect()`. In `crates/server/src/write.rs#patch_item` write `check_ac: body.check_ac.into_iter().collect()`. `PatchRequest.check_ac` stays `Option<usize>`, so the web types do not change.
4. Red. In `ticking_a_criterion_changes_only_that_box` change `check_ac: Some(2)` to `check_ac: vec![2]` and add two cases after the existing assertion.
