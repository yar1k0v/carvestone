## Description

Second build step of ADR-13. The Architecture page gets an HLD view (context, containers, topics, docs marked hld) and an LLD view per container (the service page of CS-93: diagram, modules, entry points, patterns, flows, docs marked lld). A container on the HLD view opens its LLD; the LLD has a link back to the HLD. Same engine answers as the CLI views of CS-136.

## Acceptance criteria

- [x] The Architecture page shows an HLD view and an LLD view per container, each reached from the other
- [x] The HLD view lists containers, how they connect and the docs marked hld
- [x] The LLD view shows the service page and the docs marked lld that link the container
- [x] pnpm --dir web typecheck, lint, test and build pass

## Outcome

The Architecture page opens on a two-way switch, HLD and LLD. The HLD lists the systems and containers with their descriptions and technology, how they connect (each uses entry with its phrase as written), the Rel lines of the Context and Container diagrams, and the docs marked hld; each empty section says so in one line. A container in the HLD opens its low-level design, the service page, which lists the docs marked lld that link the container with the path#Symbol where each flow starts, and has a Back to HLD link. The LLD tab shows the drawn diagrams as before and a row of links to every container's low-level design, so each level is reached from the other. The server answers GET /api/arch/hld and GET /api/arch/lld/<container> from the same engine functions as the CLI, and the web types are generated from them.
