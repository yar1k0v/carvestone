## Description

Part of CS-99. Dart imports resolve (relative paths, package:<name>/ against each pubspec.yaml name, part and part of, export) so stone code uses and deps work between Dart files, within each Flutter project and never across two projects that share a package name. See batch B2 in .planning/v1/m14.md.

## Acceptance criteria

- [x] package:<name>/x.dart and relative imports resolve to the file; stone code deps and uses cross Dart files.
- [x] Two projects with the same pubspec name resolve inside their own project only.
- [x] part / part of and export chains resolve; an unresolved import is kept as an external package, not an error.
- [x] Calls, extends, implements and with link types and members across files.

## Outcome

B2 done. New crates/graph/src/resolve_dart.rs replaces the same-file stand-in (deleted from resolve.rs); CODE_GRAPH_VERSION 9. Imports: relative paths against the importing file, never leaving its pubspec project; package:<name>/x.dart is lib/x.dart of the importing file's own project when the names match (the fleetwise twin case: two apps, one name, never linked), else a project it references by path, else another project of that name (the nearest; a tie names nothing); dart:, external packages and files not in the index (generated .g.dart) give no edge and no error. Libraries: part / part of (by file or by library name) share one scope and the library file's imports; export chains followed with show/hide at every step and cycle-safe; as-prefixes reach names only as p.Name. Names resolve enclosing type and bases, then the library, then imports. Edges: Imports (file to file, exact), extends = inherits, with/implements/on = implements, calls (plain, this/super, import prefix, type name for statics and named constructors, a receiver whose declared type is a field, parameter, variable or getter type), references (types, annotations, static receivers, bare arguments). A receiver typed with a type outside the repo (Dio, WidgetRef, BuildContext) gives no edge; a receiver of unknown type falls back to the method name inside the project (one inferred edge, or a name bucket scoped to the pubspec); about 40 ubiquitous names (add, map, build, toString ...) never take part. Dispatch: dispatch.rs gets a Dart rule (interface class: all methods; abstract/sealed class and mixin: body-less methods); dart.rs now prefixes body-less methods and accessors with 'abstract ' in their signature so the rule can see them. Engine: code_index.rs adds the stem of a new Dart file to the re-resolve names (and dependents matches Dart directives by file stem) so an importer finds a file added later, even a barrel with no declarations. Tests: graph dart_resolve (18), engine code_dart (two new: uses/deps inside each twin app, new barrel + rename + delete equal a rebuild).
