## Description

An agent sets code roots and SCIP indexes with one command, on any store. The file keeps its comments and other lines, and bad values are refused before saving. Config never holds a command to run.

## Acceptance criteria

- [x] `cargo test -p carvestone-engine --test features config_edit::` → exits 0, `0 failed`, and the new tests pass
- [x] `cargo clippy --workspace --all-targets -- -D warnings` → exits 0
- [x] `target/debug/stone.exe config add-scip-index --help` → prints `--language` and `--extensions`

## Plan

Config stays data only: this command never writes a command to run (ADR-17). The file keeps its comments and its other lines.

1. Add `crates/engine/src/edit_config.rs` with `Repo::add_code_root(&self, path: &str, dry_run: bool) -> Result<Written, EngineError>` and `Repo::add_scip_index(&self, entry: &ScipIndexEntry, dry_run: bool) -> Result<Written, EngineError>`, using `crates/store/src/config.rs#ScipIndexEntry`. Follow `crates/engine/src/edit_tasks.rs#Repo::connect`: take the lock, re-read, compute, save. Add the module to `crates/engine/src/lib.rs`.
2. Both change the raw text of the config file, never a re-serialized copy. When the key is missing, append its block at the end of the file. When the key is a block list, insert after its last item. When the key is an inline list such as `code_roots: [a]`, change that one line, and for `scip_indexes` replace an empty `[]` with a block. Any other shape is refused, with a sentence that names the key and says to edit the file by hand.
3. Keep the file's line ending. A value already present gives no diff. For `scip_indexes`, the same `file` with different fields is refused, with a sentence that names the entry.
4. Before saving, run `crates/store/src/config.rs#Config::parse` on the new text and refuse when it fails, passing on its sentence. `add_code_root` also refuses an absolute path or one holding `..`, the same way `scip_indexes` does.
5. In `crates/cli/src/main.rs`, add `config add-code-root <PATH> [--dry-run]` and `config add-scip-index <FILE> --language <L> --extensions <a,b> [--dry-run]`. Add both to `CLI_NESTED` in `crates/engine/src/guide.rs`, and name them in the code line of `crates/engine/src/guide/overview.md`.
6. Test choice: add. New public behavior and a saved format. Create `crates/engine/tests/features/config_edit.rs`, and add it to the features test list. One table test for the file shapes: key missing, block list, inline list, empty `[]`, a comment line beside the key, and CRLF. Each row asserts the whole expected file, written by hand, and that a repeat gives no diff. It catches a write that loses a comment or changes a line ending, and misses nothing a reader sees.
7. One table test for every refusal in steps 2, 3 and 4.
8. Run `cargo build --bin stone`, then the acceptance commands.
