## Description

The workspace has 104 integration test files (about 740 tests), and each file links into its own test binary; there is no tuning of the dev or test build profile and no test timing on record. Goal: the full suite builds and runs noticeably faster with the same behaviour covered. Start by recording a baseline (build time with no run, run time, the slowest tests). Then apply what Rust testing guidance recommends: one integration test binary per crate with a module per topic, a lighter debug setting for tests, optimised builds for heavy dependencies (SQLite, tree-sitter) in tests, shared fixtures instead of one repo built per test, and no sleeps or repeated indexing. Remove tests that duplicate another, only restate the implementation, or cover behaviour that no longer exists, and list each removal with the reason in the outcome. CI keeps running the commands in CLAUDE.md; switching the runner (nextest) is proposed to the product owner, not done. CLAUDE.md's single-file rule (cargo test -p <crate> --test <file>) needs updating if test binaries merge.

## Acceptance criteria

- [x] Baseline and final numbers (build, run, slowest 10) are in the outcome
- [x] cargo test --workspace passes
- [x] cargo clippy --workspace --all-targets -- -D warnings
- [x] Every removed test is listed with its reason, and no behaviour named in an acceptance criterion loses its test
- [x] CLAUDE.md test commands match the new layout

## Baseline

Measured 2026-10-31 on a 16-CPU machine. Before: cargo test --workspace takes 375 s with a warm build and 420 s on a second run with everything built; 121 test binaries run one after another and about 269 s of that is test time. Relinking all test binaries after touching crates/core takes 50 s. Slowest binaries: git_product 15 s, product_arch 14 s, code_refresh 13 s, code_framework 10 s, modules 9 s. First try: [profile.dev] debug = line-tables-only plus opt-level 2 for dependencies cut the relink to 9 s (cold build 83 s); the full run was not measured because it was stopped. Runs are heavy on the machine, so any measurement needs the owner's go.

## Outcome

The suite runs in under half the time and relinks twice as fast, with the same behaviour covered. Numbers were taken on 4 cores at below-normal priority (the owner's CPU limit); the baseline in this task was taken on 16 cores, so the like-for-like pairs are the ones measured here.

Layout: every crate with several test files now has one test binary, `crates/<crate>/tests/it/main.rs` with a module per former file (engine, graph, cli, server, mcp, index, git). Test binaries went from 121 to 20 (7 `it` binaries, store's `roundtrip`, 9 unit-test binaries and the 3 kept apart: `bench_code`, `bench_search`, `output_cost`). Test counts per crate were equal before and after the move (core 41, store 75, index 14, git 27, graph 174, engine 539, mcp 21, server 53, cli 83); the removals below are the only change since. No test sets process-wide state (no set_var, current dir or fixed port), and every temp path carries the process id and a counter, so none needed a lock.

Cause of the slow tests: the index file was built with one disk sync per table statement. A first open of any store cost about 0.45 s on Windows (stone check on an empty store: 450 ms first run, 44 ms with the file in place), and almost every test opens a fresh store. The build now runs in one transaction (crates/index/src/rebuild.rs), 0.08 s per fresh store. This also makes the first `stone` command in a new folder faster for users.
Other fixes: the three-repo product and the plain git repo are built once per run and copied (they cost 24 and 6 git processes per test); git init uses no sample hooks; the two 1,200-commit histories in git_cache are built once and copied.

Run time (sum of test binaries, same limits): engine `it` 166 s before, 67 to 74 s after; whole workspace about 119 s after. Slowest engine tests before: random_edits 18.3 s, git_product stale 11.6, product_arch no-parsed-code 11.5, check fixtures 11.0 and 10.9, modules 10.3. Slowest 10 after: git_product stale 9.4 s, product_arch no-parsed-code 9.2, code_refresh one_file_under_one_second 7.4, git_product broken repo 6.1, service_map shared projects 4.5, refresh batched fill 4.4, product_arch portal drift 4.3, git_cache unshallow 4.0, code_refresh random_edits 3.9, one at 3.8. What is left is git processes (a test that makes 10 commits starts 30 git processes at 60 ms each) and index schema::reader_during_bump, which waits out a 5 s rename lock on Windows by design.

Profile: `[profile.dev] debug = "line-tables-only"` and `[profile.dev.package."*"] opt-level = 2` are applied. Relink after touching crates/core: 47.8 s before, 23.5 s after (cold build with the profile 131 s). Run time with the profile is not slower: engine `it` 67.1 and 73.4 s without, 74.4 and 70.5 s with; cli 20.6 s without, 20.2 and 20.7 s with. CI cold builds take longer once because dependencies compile at opt-level 2.

CLAUDE.md: the `--test <file>` line now describes `--test it <topic>::` with a count check. Old task proofs in stone (CS-98, 116, 117, 118, 125, 130) still name `--test <file>`; they are history and were left as written.

Removed tests, none the only test of a criterion:
- index::schema::old_version_is_rebuilt_without_rows: repeated by schema_v3_rebuilds_v2_db, which checks the same rebuild and more.
- index::schema::four_threads_open_old_db_with_one_rebuild: repeated by schema_v3_four_threads_open_v2_db.
- index::schema::open_twice_keeps_rows: repeated by upgrade::current_file_is_kept.
- engine::import_apply::import_twice_is_noop: repeated by import_run::import_twice_no_diff (both importers).
- engine::import_apply::dry_run_writes_nothing: repeated by import_run::dry_run_leaves_nothing.
- engine::import_apply::source_change_updates_an_untouched_target: repeated by import_run::one_source_change_one_file.
- mcp::read_tools::lists_read_tools_in_order: the tool list and server name are asserted by server::initialize_names_stone_and_lists_tools.
- mcp::code_tool::tools_list_has_code_after_the_three_base_tools: position of `code` is covered by the same exact list.
