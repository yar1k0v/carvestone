## Description

From the Fleetwise session. A page made with a wrong slug (docs/lld-flow-device-frame instead of docs/lld-backend-flow-device-frame) cannot be fixed, and only tasks can be removed (stone task remove, CS-118). Wanted: stone rename <id> <new-id> rewrites wikilinks, links and backlinks to the item; stone delete <id> works for any item type and refuses while backlinks exist unless forced. Rename conflicts with ADR-4 (filename is the id; files never move), so the product owner decides first whether to amend ADR-4 or limit rename to unnumbered items (docs, plans, refs, arch), which have slugs rather than numbers. Size: medium.

## Acceptance criteria

- [x] ADR-4 is amended, or the limit to slug items is recorded, before building
- [x] stone rename <id> <new-id> moves the item and rewrites every link and wikilink to it, in one lock; a dry run shows the changes
- [x] stone delete <id> removes any item type, refuses while backlinks exist and names them, and deletes anyway with --force
- [x] The agent guide says when to rename, delete or archive
- [x] cargo test --workspace and cargo clippy --workspace --all-targets -- -D warnings

## Outcome

stone rename <id> <new-id> gives a doc, plan, reference or architecture item a new id in its folder and rewrites every link to it in one write: relation fields, wikilinks, markdown links, diagram box links and #anchor forms. A numbered item is refused with the alternatives, a taken or malformed new id is refused with the reason, --dry-run lists the changes and writes nothing, and running it again says no change. stone delete <id> removes an item of any type, refuses while items link to it and names them, and with --force deletes anyway and lists the links it breaks; stone task remove shares its code and works as before. ADR-4 was amended to allow renaming slug items. The agent guide and the agent block say when to rename, delete or archive.
