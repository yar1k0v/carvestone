## Description

Running stone init inside an existing git repo writes no code_roots, so the code index stays empty and code find answers no matches with exit 0 and no note. Seen in games/crawl-away with C# files, where code_roots is not yet read. Reproduced in a scratch repo: init inside the repo finds nothing, init above it finds the class. Cause: create.rs sets code_roots to an empty list when the root is in a repo, and candidates in code_index.rs returns nothing for an empty list.

## Plan

1. In `crates/engine/src/create.rs#init_with`, when `in_repo` is true, set `code_roots` to `vec![".".to_string()]`, so the config holds `code_roots:` with one `.` entry. Keep `Vec::new()` nowhere on that branch. Update the doc comment of `init`.
2. In `crates/cli/src/main.rs`, where `init` prints `code roots: {n} project repo`, print `code roots: the whole repo` when `done.code_roots` is exactly `["."]`. Keep the other line for every other value.
3. In `crates/engine/src/owner.rs#Repo::ownership`, return early with `problems` when every entry of `root_prefixes(roots)` is empty and `first_code_item(snapshot)` is `None`. Reason: a new project has no components yet, and `check` must not fail on every file. A store with named roots keeps today's check.
4. In `crates/engine/src/code.rs#find`, when `repo.store.config.code_roots` is empty and the result has no hits, set `note` to: `no code is indexed, because stone/config.yml has no code_roots; add code_roots: [.] to index the whole repo`. Any building note wins over it. The CLI already prints `note:` through `code_tail`.
5. Test choice: add, because `init` inside a repo has no test and this is a saved format. In `crates/engine/tests/features/workspace.rs`, add `init_inside_a_repo_indexes_the_whole_repo`, using the git helpers of `crates/engine/tests/features/support.rs`, with one untracked `game/Player.cs`. Expect the literal `code_roots` lines in `stone/config.yml`, `Player` found by `carvestone_engine::code::find`, and no `owner` problem from `check`. It catches an empty list, a `.` root that lists no files, and an owner error per file. It misses the CLI wording, which the last criterion covers.
