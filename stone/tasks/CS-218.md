## Plan

Agents append to `## Notes` by reading the section and writing it all back, which risks losing lines. The engine already has `Edit.note` (`crates/engine/src/edit.rs#add_note`, a dated bullet, once). Only the CLI flag is missing.

1. In `crates/cli/src/main.rs#EditArgs`, add `#[arg(long, allow_hyphen_values = true)] note: Option<String>` with the help line: `Add a dated bullet to ## Notes; the same text twice adds it once.` Pass it as `note: args.note` where `Edit` is built in `run` (today `note: None`).
2. In `crates/engine/src/guide/` (the do and finish guides, whichever tell agents to write Notes by rewriting the section), replace that advice with `stone edit <id> --note "<text>"`. `crates/engine/tests/features/guide.rs` already checks that every `stone <cmd>` in the guides is real.
3. Test choice: patch. `crates/engine/tests/features/tasks.rs#a_note_lands_under_notes_once` covers the engine. Add one row to the CLI smoke test in `crates/cli/tests/features/main.rs` that runs `edit <id> --note "x"` twice and asserts one `- <date>: x` line. It catches the flag not reaching the engine.
4. Run `cargo build --bin stone`, then the acceptance commands.

## Outcome

stone edit takes --note <text>, which adds one dated bullet under ## Notes (the same text twice adds it once). The do, finish and overview guides name it. Checked with the CLI features test (3 passed, new note row) and guide:: (2 passed).
