## Description

stone arch connect writes a connection in one call: from, to, what it does and a protocol. Any protocol works, so no stack is locked out. Code marks a written connection as agreed only for build-time links, and never flags a run-time connection as wrong.

- [x] `cargo test -p carvestone-cli` → exits 0, `0 failed`
- [x] `cargo clippy --workspace --all-targets -- -D warnings` → exits 0
- [x] `target/debug/stone.exe arch connect --help` → prints `--does` and `--over`

## Plan

The storage exists: a connection is a `uses` entry plus a `## Uses` bullet, `- [[to]]: phrase (technology)`. The drift check already skips a bullet that leaves the process. Add no new field. This task adds one command, and removes the stack lock in the protocol list.

1. In `crates/core/src/section.rs#split_technology`, also accept a trailing `(over X)` for any X: the description is the text before it, and `technology` is X. Keep today's `REMOTE` list for existing bullets. Keep the `over` word out of `technology`.
2. Test choice: patch. Add rows for `Sends frames (over NATS)`, `Reads items (HTTP)` and `Parses ids (internal)` to the closest existing `uses_bullets` test. If none exists, add one table test in `crates/engine/tests/features/architecture.rs` through `check` or `hld`, and say why. It catches a run-time connection flagged as drift on a stack the list does not name.
3. In `crates/engine/src/edit_tasks.rs`, add `Repo::connect(&self, from: &str, to: &str, does: &str, over: Option<&str>, dry_run: bool) -> Result<Written, EngineError>`, beside `Repo::link` and in its style: take the lock, re-read, compute, save.
4. `connect` refuses, with a plain sentence naming the next step: a `from` or `to` that is not an existing system, container or component; `from` equal to `to`; `does` empty or over `USES_MAX_WORDS` words.
5. `connect` adds `to` to `uses` when missing, and writes the bullet in `## Uses`, creating the section when missing. A bullet for `to` already there is replaced, and no other line changes. The same call twice gives no diff.
6. The bullet is `- [[to]]: does` with ` (over X)` when `over` is given.
7. In `crates/cli/src/main.rs`, add `arch connect <FROM> <TO> --does <TEXT> [--over <PROTOCOL>] [--dry-run]` to the `arch` subcommands. Add `("arch", "connect")` to `CLI_NESTED` in `crates/engine/src/guide.rs`.
8. Test choice: add. New public behavior and a saved format. In `crates/engine/tests/features/architecture.rs`: one test that connects two components, then asserts the `uses` list, the bullet, `hld` output, and no diff on a repeat; one table test for every refusal in step 4.
9. In `crates/engine/src/guide/overview.md`, name `stone arch connect` in the Design levels line.
10. Run `cargo build --bin stone`, then the acceptance commands.
