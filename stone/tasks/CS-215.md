## Plan

`stone edit --section` reaches only text under a `##` heading. The text before the first heading (a milestone's whole body, for example) cannot be changed through stone, and the store guard bars direct writes. An agent tried `--section body` and got a new `## Body` section instead. Lead decision: the section name `body` means that text, unless the item has its own `## Body` heading, which wins.

1. In `crates/engine/src/edit.rs#replace_section`: when no heading matches `name` and `name` is `body` (any case), replace the text before the first level-2 heading with `text` and keep every section after it unchanged. Same text as held leaves the body alone, as for other sections. Keep the line ending of the body (`crates/core/src/section.rs#eol`). An item with no heading at all: `text` becomes the whole body.
2. If a helper is needed to find where the first section starts, use `crates/core/src/section.rs#sections` (its first `Section`'s start line). Write no second heading scanner.
3. In `crates/cli/src/main.rs`, add one sentence to the `--section` help of `edit`: `body` names the text before the first heading.
4. Test choice: patch. In `crates/engine/tests/features/items.rs`, add rows in the style of `an_edit_changes_only_its_lines_and_keeps_crlf`: (a) a milestone with text and no headings, `section("body", ...)` replaces it all; (b) an item with text before `## Notes`, only that text changes and `## Notes` stays byte for byte, with CRLF kept; (c) an item with a `## Body` heading, that section changes and the text above stays. It catches a body edit that drops later sections or adds a `## Body` heading. Prove each row fails before the change.
5. Run `cargo build --bin stone`, then the acceptance commands.

## Outcome

stone edit --section body now replaces the text before the first heading (an own ## Body heading wins), keeping later sections and CRLF. Checked by a new items:: test (12 passed), full clippy, fmt and workspace tests, and an M-3 dry run.
