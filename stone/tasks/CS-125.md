## Description

Found by the Dart trial (CS-122). Every extractor puts grammar failures in FileFacts::warnings (file and line) but the engine never stores or prints them, so a user cannot tell which files parsed with errors. Keep them per file in the index and list them in a query or in stone check output (count plus the first few with path:line). Applies to all languages. Repro: put a syntax error in any Dart file, refresh, nothing says so.

## Acceptance criteria

- [x] A file that parsed with errors is kept per file in the index and stone check lists the count, the number of files and the first five as path:line: cargo test -p carvestone-engine --test code_warnings
- [x] Fixing the file removes the warning; a clean tree shows none: cargo test -p carvestone-engine --test code_warnings
- [x] The schema version is bumped for the new table: cargo test -p carvestone-index
- [x] cargo clippy --workspace --all-targets -- -D warnings

## Outcome

Stone check now lists files that parsed with syntax errors, in any language: one warning with the number of errors and files and the first five as path:line. The warnings are kept per file in the code index (schema version 8) and go when the file is fixed.
