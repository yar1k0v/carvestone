## Description

One call lists containers with no code, code with no owner, parts with no connection or doc, and written build-time links the code contradicts. An agent sees what to do next.

## Plan

Reads only. Every gap names the next command, so an agent can work down the list. A run-time connection is never a gap (ADR-17).

1. Add `crates/engine/src/arch_gaps.rs` with `pub fn gaps(repo: &Repo) -> Result<Gaps, EngineError>`. `Gaps` holds `items: Vec<Gap>`. `Gap` holds `kind: GapKind`, `id: String`, `detail: String` and `next: String`. `GapKind` is an enum, in this order: `NoCode`, `UnownedCode`, `NoConnection`, `NoDoc`, `ContradictedLink`. All derive `Serialize`, as `crates/engine/src/arch_graph.rs#DriftFinding` does. Add the module to `crates/engine/src/lib.rs`.
2. Build it from `crates/engine/src/arch_graph.rs#arch_graph`. Write no second reader of arch items.
3. `NoCode`: a node of type `container` or `component` with an empty `code`. `next` is `stone map`.
4. `UnownedCode`: each draft that `crates/engine/src/scan.rs#scan` reports with `dry_run` on, in state New or Changed. `id` is the draft path. `next` is `stone scan`. A store with no code roots gives none, and nothing is written.
5. `NoConnection`: a node of type `container` that is on neither side of any `uses` edge. `next` is `stone arch connect <id> <to> --does <text>`.
6. `NoDoc`: a node of type `container` that no doc links to, read from the same snapshot `crates/engine/src/design.rs#hld` reads. `next` is `stone new doc --title <title> --link <id>`.
7. `ContradictedLink`: each `DriftFinding` of `ArchGraph.drift`, with its `problem` text as `detail`. `next` is `stone arch connect` for `DriftKind::Code`, and `stone edit <id>` for `DriftKind::Uses`.
8. Sort by kind, then id. Same store, same output.
9. In `crates/cli/src/main.rs`, add `arch gaps` with `--json`. Text output is one line per gap: kind, id, detail, then the next command on its own indented line. An empty list prints `no gaps`. Exit 0 either way, because gaps are work and not errors. Add it to `CLI_NESTED` in `crates/engine/src/guide.rs`, and name it in the Design levels line of `crates/engine/src/guide/overview.md`.
10. Test choice: add. New public behavior with real branches. In `crates/engine/tests/features/architecture.rs`, one fixture store with one case of each kind and one clean container, asserting the exact list. It catches a kind that fires on a complete part. A second assertion: a connection with `(over NATS)` and no code edge gives no `ContradictedLink`.
11. Run `cargo build --bin stone`, then the acceptance commands.
