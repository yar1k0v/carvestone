## Plan

Today `search`, `precedents` and `why` end a cut answer with a count only, such as `2 more results left out; raise --limit or --budget`. After this task each one names what it left out and its size, in the same form as the tiers of CS-232: `left out: hits (2 lines, about 21 tokens); raise --limit or --budget`.

Owner decisions (Notes): the code lists (`CodeResult`, `Outline`, `Impact`, `PathResult`, `Explain`, `Entries`) move in a follow-up task and keep `code_tail` here. Search hits past the SQL `LIMIT` of `crates/engine/src/search.rs#candidates` and `crates/engine/src/search.rs#symbol_hits` get no estimate and no extra count query: the line says `and more not counted`.

The size rule, the same as `crates/engine/src/tiers.rs#fit`: `lines` is the count of dropped printed lines, `tokens` is `tiers::tokens` of those lines joined by `"\n"`. A block heading that disappears because its last entry was dropped is not counted.

Outside names: `crates/engine/src/tiers.rs#LeftOut`, `crates/engine/src/tiers.rs#tokens`, `crates/engine/src/tiers.rs#notice`, `crates/cli/src/lean.rs#fit`, `crates/cli/src/lean.rs#search_lines`, `crates/cli/src/main.rs#code_tail`, `crates/engine/tests/ts_export.rs`.

1. Seam: `crates/engine/src/tiers.rs#left_out_line` (new). It catches a wrong noun (`1 lines`), a missing `and more not counted`, and a wrong raise hint. It misses which lines a command drops (steps 3 to 5 cover that). Test choice: add one table test `the_left_out_line_names_what_was_cut_and_its_size` (new) to `crates/engine/tests/features/tiers.rs`, because the function is new public behavior. Rows, each `(LeftOut, more_uncounted, raise)` and the exact result:
   - `{ name: "hits", lines: 2, tokens: 21 }`, `false`, `"--limit or --budget"` → `left out: hits (2 lines, about 21 tokens); raise --limit or --budget`
   - `{ name: "entries", lines: 1, tokens: 9 }`, `false`, `"--budget"` → `left out: entries (1 line, about 9 tokens); raise --budget`
   - `{ name: "hits", lines: 2, tokens: 21 }`, `true`, `"--limit or --budget"` → `left out: hits (2 lines, about 21 tokens) and more not counted; raise --limit or --budget`
   Stub first: the function returns an empty `String`, so the test fails on its assertions.
2. `crates/engine/src/tiers.rs`:
   - `LeftOut` gets `Serialize` in its derive list and `#[cfg_attr(feature = "ts", derive(ts_rs::TS))]`, as `crates/engine/src/search.rs#SearchResult` has it.
   - `pub fn left_out_line(left: &LeftOut, more_uncounted: bool, raise: &str) -> String` (new): `left out: {name} ({lines} {line|lines}, about {tokens} tokens){" and more not counted" when more_uncounted}; raise {raise}`. Write `1 line` the way `notice` does. `notice` stays as it is.
   - `pub fn left_out(name: &str, dropped: &[String]) -> Option<LeftOut>` (new): `None` for an empty slice, else `LeftOut { name, lines: dropped.len(), tokens: tokens(&dropped.join("\n")) }`.
3. `crates/engine/src/search.rs`:

Doc comments: `left_out` is the size of the hits the limit or the budget dropped; `uncounted` means the index returned its full candidate cap, so more hits may exist that were never read. `omitted` stays.
   - `Candidate`: add `title: String` and `text: String`. `candidates`: select `s.title, s.text` as columns 10 and 11 and fill the two fields. In `search`, the loop builds the snippet from `c.title` and `c.text` and runs no `SELECT title, text` per hit any more.
   - Set `uncounted` to true when a `candidates` call returned `CANDIDATES` rows (read the length before `found.retain`) or `symbol_hits` returned `SYMBOL_CANDIDATES` rows.
   - After the loop stops at the limit or the budget, go on over the rest of `ordered`: build each hit the same way (snippet included) and collect `hit.line()` into `dropped`. Then `left_out = tiers::left_out("hits", &dropped)`. `omitted` stays `total - hits.len()`.
