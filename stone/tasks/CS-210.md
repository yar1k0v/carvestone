## Plan

Copy how CS-201 added the debug topic: `crates/engine/src/guide/debug.md` and `Topic::Debug` in `crates/engine/src/guide.rs`.

1. Add `crates/engine/src/guide/design.md`, in the shape of the other guide files, with these numbered steps and nothing else. Every command in it must exist today.
   1. Read first: `stone init` when the repo has no store, then `stone arch hld` and `stone arch gaps`.
   2. Parts: `stone new system --title <name>`, then `stone new container --title <name>`, and set `parent`, `description` and `technology` with `stone edit`. A container is something that runs or stores data. A library is a component.
   3. Connections: `stone arch connect <from> <to> --does <text> --over <protocol>`, one per direction, from the side that starts it. `--does` is a verb phrase, never `Uses`. `--over` is required when the connection leaves the process.
   4. Code: `stone config add-code-root <path>`, then `stone map --write`, then `stone scan`. A language with no built-in parser needs `stone config add-scip-index`, then `stone code native`.
   5. Docs: `stone new doc --title <title> --link <id>`. A flow through several parts stays a `C4Dynamic` mermaid fence in a doc.
   6. Finish: repeat `stone arch gaps` until each gap left is one the owner accepts, then `stone check`.
