## Description

Today's stone map proposes code folders for architecture items. It moves to stone arch map, with the same flags and output, so the name stone map is free for the project map (CS-231). Every hint, guide, test and doc that names the old command follows.

## Acceptance criteria

- [ ] `cargo test -p carvestone-engine --test features architecture::` → `N passed` with N above 0, 0 failed
- [ ] `cargo test -p carvestone-engine --test features guide::` → `2 passed`, 0 failed
- [ ] `cargo test -p carvestone-cli --test features` → `3 passed`, 0 failed
- [ ] `target/debug/stone.exe arch map` → `every container and component names its code`
- [ ] `target/debug/stone.exe map` → exit code 2 and `unrecognized subcommand 'map'`
- [ ] Grep `stone map` in `crates/`, `README.md` and `stone/docs/feature-architecture.md` → no match
- [ ] `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace` → all pass
- [ ] `target/debug/stone.exe check` → no new problem (the one warning on cli.md is known)

## Plan

The behaviour does not change: only the name. After this task `stone map` is an unknown command until CS-231 adds the project map.

Test choice: patch, in steps 1 and 2. Two existing rows hold the old name. They catch a hint or a parser that still says `stone map`. They miss the hint lines of `render_map` after `--write`, which no test reaches; the Grep criterion covers those.

1. `crates/engine/tests/features/architecture.rs`: in the row `(GapKind::NoCode, "arch/shop/ghost", "stone map --write")`, the text becomes `"stone arch map --write"`. Run `cargo test -p carvestone-engine --test features architecture::`: it must fail on that row.
2. `crates/cli/tests/features/main.rs#every_command_answers_on_a_small_store`: the row `&["map"]` becomes `&["arch", "map"]`, with the same expected text.
3. `crates/engine/src/arch_gaps.rs#gaps`: the `GapKind::NoCode` next step `"stone map --write"` becomes `"stone arch map --write"`.
4. `crates/cli/src/main.rs#Command`: remove the variant `Map` with its doc comment and its two arguments. Add the same variant, doc comment and arguments to `crates/cli/src/main.rs#ArchCommand`, after `Gaps`.
5. `crates/cli/src/main.rs#run`: remove the arm `Command::Map { write, pick }`. Move its body, unchanged, into a new function `fn run_arch_map(repo: &Repo, write: bool, pick: &[String], json: bool) -> anyhow::Result<String>` placed above `run_arch`. It returns the `render_map(...)` result where the arm printed it.
6. `crates/cli/src/main.rs#run_arch`: add the arm `ArchCommand::Map { write, pick } => run_arch_map(repo, *write, pick, json)?`.
7. `crates/cli/src/main.rs#render_map`: the two hints ``run `stone map` to see them`` become ``run `stone arch map` to see them``, and ``run `stone map --write` to save`` becomes ``run `stone arch map --write` to save``.
8. `crates/cli/src/main.rs#render_lld`: ``or run `stone map` `` becomes ``or run `stone arch map` ``.
9. `crates/engine/src/guide.rs#CLI_COMMANDS`: remove `"map"`. `crates/engine/src/guide.rs#CLI_NESTED`: add `("arch", "map")` after `("arch", "gaps")`.
10. `crates/engine/src/guide/design.md`, step 4: `stone map --write` becomes `stone arch map --write`.
11. `crates/engine/src/agent_block.rs#TABLE`: in the row `Which folder holds each service`, the command becomes `` `stone arch map` ``.
12. `crates/engine/src/service_map.rs`, first line of the module comment: `stone map` becomes `stone arch map`.
13. `README.md`, the line that starts ``- `stone map` and `stone scan` ``: `stone map` becomes `stone arch map`.
14. `target/debug/stone.exe edit docs/feature-architecture --section commands`: the same table, with the row `stone map [--write]` changed to `stone arch map [--write]`. Then `--section limits`: the same text, with ``Run `stone map` `` changed to ``Run `stone arch map` ``. Read each section with `get docs/feature-architecture#commands` and `#limits` first, and send the whole section back.

Not changed: `stone/docs/prd.md` (deprecated), finished tasks that name the old command, and `crates/engine/src/guide.rs#names_unknown_command` (it reads the two lists).
