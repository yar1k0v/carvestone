## Description

`stone export --okf <folder>` writes a copy of the store in which every relation is a standard markdown link (OKF v0.2 section 6.1): body wikilinks become inline links, and the relation fields become a `## Links` section at the end of each file. The copy goes to a separate folder and is one-way; the store is not changed. For other OKF tools, which read only markdown links.

## Plan

Format (decided, do not change):

- The export holds every item at `<folder>/<id>.md` and every `index.md` and `log.md` of the store at the same relative path, copied as it is. `config.yml`, `stone/files/` and `.git` are not copied.
- Frontmatter is copied unchanged. The relation fields stay in it.
- Link form: the path from the folder of the exported file to the target file, with `/`, with `.md`, without a leading `./`, and with `#anchor` kept. Same folder: `CS-2.md`. Other folder: `../docs/setup.md#overview`. From `arch/acme/api/auth.md` to a task: `../../../tasks/CS-1.md`.
- Body wikilink `[[target]]` that `Snapshot::resolve` finds: `[<target as written>](<link>)`.
- `[[code:<rest>]]`: the code span `` `<rest>` `` (code is outside the bundle).
- A wikilink that does not resolve stays as written and is reported.
- Wikilinks in fences and code spans, `$link` values in diagrams, and existing markdown links are not changed.
- `## Links` comes last in the file, after one blank line, only when the item has a relation value. One `### <field>` group for each relation field with values, in the order of `RELATION_KEYS` (`links`, `depends_on`, `components`, `uses`, `milestone`, `plan`, `supersedes`, `parent`), values in frontmatter order. A value that resolves: `- [<link text>](<link>)`, link text from `crates/engine/src/index_file.rs#link_text` of the target. A value that does not resolve: `- <value>`, and it is reported.
- A body that already has a `Links` section still gets the new `## Links` at the end; nothing is merged.
- New text uses the line ending of the file (`carvestone_core::eol`).
