## Plan

1. Add `crates/engine/src/code_tables.rs`, with `pub mod code_tables` in `crates/engine/src/lib.rs`. Types, with the `ts` derive as in `crates/engine/src/code_domain.rs#Entity`: `Column { name, type_name, nullable, default? }`, `ForeignKey { name?, columns, table, on_delete? }`, `TableIndex { name?, columns, unique }`, `Migration { id, file }`, `Table { name, schema?, entity, primary_key, columns, foreign_keys, indexes, ddl, migration? }`, `Database { name, file, tables }`, `Tables { databases, note? }`.
2. Same file: `pub fn parse_snapshot(text: &str) -> ParsedSnapshot`, with `tables: Vec<Table>` and `left_out: usize`. Read `modelBuilder.Entity("<full name>", b =>` blocks by brace depth, merging blocks of one entity, because EF writes properties and relations in separate blocks. Inside a block read each statement up to its `;`: `b.Property<T>("P")` and `b.PrimitiveCollection<T>("P")` with `.HasColumnType`, `.HasColumnName`, `.IsRequired`, `.HasDefaultValue`, `.HasDefaultValueSql`; `b.HasKey`; `b.HasIndex` with `.IsUnique` and `.HasDatabaseName`; `b.ToTable("t")` and `b.ToTable("t", "schema")`; `b.HasOne("<entity>", ...)` with `.HasForeignKey`, `.OnDelete(DeleteBehavior.X)`, `.HasConstraintName`.
3. Same function, the rules. The column name is `HasColumnName`, else the property. A column is not nullable when `.IsRequired()` is written, or when `T` is one of bool, byte, short, int, long, float, double, decimal, Guid, DateTime, DateTimeOffset, DateOnly, TimeOnly or TimeSpan with no `?`. Keys, indexes and foreign keys name properties, so turn them into column names at the end. A foreign key's `table` is the table of the entity it names. An entity with no `ToTable` is counted in `left_out`, as are `OwnsOne` and `OwnsMany` blocks, and never fails the read.
4. Same file: `fn ddl(table: &Table) -> String`. `CREATE TABLE <name> (`, one line per column with `<name> <type>`, then `NOT NULL` and `DEFAULT <value>` when known, `PRIMARY KEY (...)`, one `CONSTRAINT <name> FOREIGN KEY (...) REFERENCES <table> ON DELETE <X>` each, `);`, then one `CREATE [UNIQUE] INDEX <name> ON <table> (...);` each. `DeleteBehavior` words: Cascade is `CASCADE`, SetNull is `SET NULL`, Restrict is `RESTRICT`, NoAction is `NO ACTION`. The DDL is generated, so the page can say so.
5. Same file: `pub fn tables(repo: &Repo) -> Result<Tables, EngineError>`. Open the index and `code_map` as `crates/engine/src/code_domain.rs#domain` does. Take the syms whose name ends in `ModelSnapshot`, and read each file from `repo.store.layout.root`. The database name is the class name without `ModelSnapshot`, then without `DbContext` or `Context`. An unreadable file is skipped and named in `note`. With `left_out` above 0, `note` says how many entities were left out. No snapshot gives empty `databases` and no error.
6. Same file: `latest_migration`. List the `.cs` files beside the snapshot, leaving out `*.Designer.cs` and the snapshot, sorted by name, newest first, and take the first whose text holds the table name in quotes. Read each migration once per database, not once per table. `id` is the file stem.
7. `crates/server/src/code_routes.rs`: add `tables`, as `settings` does. `crates/server/src/lib.rs`: route `/api/code/tables`, and add it to the warm list beside `/api/code/domain`. Generate `web/src/api/types` with the crate's `ts` feature, as earlier API tasks did, and commit nothing.
8. Test choice: add `crates/engine/tests/features/tables.rs`, with `mod tables` in the features main, because this is a new parser. Use a hand-written snapshot const, never copied from Fleetwise. One table test with literal expected values: nullable rules for `Guid`, `Guid?`, `string`, `string` with `IsRequired`; `HasColumnName` against no name; a composite key; a unique index with two columns; relations in a second block; a `ToTable` with a schema; an entity with no `ToTable` counted in `left_out`; a `}` or `;` inside a string value. One test of `ddl` against a literal text. One test of `latest_migration` through `tables` on a temp store, if the shared fixtures can index a C# class, else on the helper made `pub`. Add a property test that `parse_snapshot` never panics on any text. Catches a wrong nullable and a lost relation. Misses real EF output, which step 10 covers.
9. Test choice: patch `crates/server/tests/features/main.rs` with `/api/code/tables` in the route table, answering empty `databases` on a store with no code. Catches a lost route.
10. Real data, read-only: copy `../fleetwise/backend/Fleetwise.Infrastructure/Persistence/Core/Migrations` into a throwaway folder under `docs/agent-scratch/`, run `stone init` and the code index there, never in the Fleetwise repo, and call `tables` through a short-lived server, `timeout 300` on port 4748. Write nothing under `../fleetwise`. State the table count and `left_out`, compare `vehicles` with its snapshot block by hand, and remove the copy. Keep no Fleetwise text in the repo or in test fixtures.
