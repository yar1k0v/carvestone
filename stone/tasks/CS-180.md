## Description

stone precedents labels every changed file with role file, because the kind query matches only the file root symbol. Agents cannot find precedents by role, and shapes read added file instead of added function.

## Plan

1. In `crates/engine/tests/features/history.rs#precedents_find_finished_tasks_that_made_the_same_change`, change both expected `added file` values to `added function`, and correct the comment above them. Run the test and confirm it fails on that assertion.
2. In the kind query at the end of the role lookup in `crates/engine/src/precedents.rs`, count the top-level symbols of the file: `LEFT JOIN symbols p ON p.id = s.parent_id`, keep rows where `s.kind NOT IN ('file', 'project')` and (`s.parent_id IS NULL` or `p.kind IN ('file', 'project')`). Leave the `GROUP BY`, `ORDER BY` and the `file` fallback as they are. A file with no top-level symbol still gives `file`.
3. Run the acceptance commands. An old test that fails only because it expected `file` as the role: change that expected value, add its file to `paths`, and say so under `## Notes`. Any other failure: stop and report.

Seam: the role lookup. The history test catches a role read from the file root, and misses languages other than Rust, which share the same query and root symbol. Test choice: patch, the existing precedents scenario.
