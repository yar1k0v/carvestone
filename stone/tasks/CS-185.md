## Description

`stone code native` reported a failed scip-python run as `scip-python in .: }`. After this change a failed indexer reports its own error line and the file that holds its full output, and scip-python no longer fails in a repo that has no commit. ## Plan

Cause, proven by running the tool by hand as `crates/engine/src/code_native.rs#run_indexer` starts it (scip-python 0.6.8, node 24):

- scip-python ends a fatal error with an object dump on stderr. Its last line is `}`. `crates/engine/src/code_native.rs#telling` accepts `}`, and `run_indexer` keeps only the last telling line, so the report reads `scip-python in .: }`.
- In games/crawl-away the tool's own type checker stops with `error: RangeError: Maximum call stack size exceeded` (first file: `docs/concept/fx_demo.py`). A larger node stack does not help. stone cannot fix this; it can only report it.
- In a git repo with no commit the tool cannot read its version from `git rev-parse HEAD` and stops with `error: TypeError: Cannot read properties of undefined (reading 'indexOf')`. With `--project-version 0` the same run writes its index, with and without a commit.

Steps:

   - Store: `project(&[("src/a.py", "def a():\n    return 1\n")])`.

Elsewhere the file `scip-python` (mode 755) with `#!/bin/sh`, `echo "$@" >&2`, the same four lines through `echo ... >&2`, and `exit 1`. Choose with `cfg!(windows)`.
