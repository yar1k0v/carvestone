## Description

`stone code find database` and `stone search` return the top-level keys of YAML and JSON files under the code roots, with their line ranges, so an agent reads one key instead of the whole file. Config files get no edges and need no component owner (ADR-22).

## Plan

1. `Cargo.toml` `[workspace.dependencies]`: add `tree-sitter-json` and `tree-sitter-yaml`, each at the newest version that builds with `tree-sitter = "0.26"` (their `tree-sitter-language` dependency must resolve). `crates/graph/Cargo.toml`: add both with `.workspace = true`. If no version of either resolves, stop and report. Docs: https://docs.rs/tree-sitter-json and https://docs.rs/tree-sitter-yaml (the `LANGUAGE` constant, used like `tree_sitter_dart::LANGUAGE` in `crates/graph/src/dart.rs#extract_dart`).
2. `crates/graph/src/facts.rs#Lang`: add `Json` and `Yaml`; `as_str` returns `"json"` and `"yaml"`. `lang_of` maps `json` to `Json` and `yaml`, `yml` to `Yaml`, and returns `None` for the file names `package-lock.json` and `pnpm-lock.yaml` and for names ending `.min.json` (machine-written). Project files such as `package.json` and `pubspec.yaml` stay project files: `crates/engine/src/code_index.rs#candidates` checks `ProjectKind::of` first.
3. `crates/graph/src/facts.rs`: add `Lang::is_config(self) -> bool` (new), true for `Json` and `Yaml` only.
4. `crates/graph/src/config_keys.rs` (new) with `extract_json(path, src) -> FileFacts` (new) and `extract_yaml(path, src) -> FileFacts` (new):
   - First decl is the `DeclKind::File` decl, built like `crates/graph/src/dart.rs#extract_dart`.
   - JSON: each pair of the root object. YAML: each pair of the root block mapping of every document (`---` separated). Each becomes a `DeclKind::Member` with `name` the key text without quotes, `qname` `<path>#<key>`, `parent: Some(0)`, `signature` the key's first line trimmed and cut at 120 characters, lines from the pair node (1-based).
   - Nested keys, arrays and scalars at the root add nothing. No refs, no imports.
   - A tree with errors keeps the keys parsed outside error nodes and adds one `Warning` at the first error's line.
5. `crates/graph/src/lib.rs#extract`: add `Lang::Json => config_keys::extract_json(path, src)`, `Lang::Yaml => config_keys::extract_yaml(path, src)` and `mod config_keys;`.
6. `crates/graph/src/resolve.rs`: `resolver_for` returns, for `Json` and `Yaml`, a resolver that yields no edges; leave both out of `LANGS`. `crates/engine/src/code_index.rs`: `governing_kinds` returns `&[]` for both; add both to `lang_from`. Bump `crates/graph/src/lib.rs#CODE_GRAPH_VERSION` by one.
7. `crates/engine/src/owner.rs`: the ownership loop skips a file whose `lang_of` is a config language (`is_config`), as the comment there says config needs no owner.
8. `crates/engine/src/code_gap.rs`: the gap line becomes `not indexed: string literals, nested config keys`.
9. Seam: key extraction in `config_keys.rs`. It catches root keys, multi-document YAML and quoted JSON keys with their lines; it misses keys inside anchors and merges.
