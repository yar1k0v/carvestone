## Description

An agent adds several notes to a task in one `stone edit` call: `--note` repeats, as `--check-ac` does. One store write instead of one per note.

## Acceptance criteria

- [x] `cargo test -p carvestone-cli --test features` → all pass
- [x] `cargo test -p carvestone-engine --test features items::` → all pass

## Plan

1. `crates/engine/src/edit.rs#Edit`: change `note: Option<String>` to `note: Vec<String>` and its doc to "Lines to add under `## Notes`, dated today, in order".
2. `crates/engine/src/edit.rs#Repo::edit_if_match`: the guard uses `req.note.is_empty()`. Replace `if let Some(text) = &req.note` with a loop over `&req.note` that calls `add_note` for each, in order. `add_note` already skips a text that is there, so a repeated text is added once.
3. `crates/cli/src/main.rs`: the edit arg `note` becomes `Vec<String>` with doc "Add a dated bullet to ## Notes; repeat for more; the same text twice adds it once". Keep `allow_hyphen_values = true`. Pass `note: args.note`.
4. `crates/server/src/write.rs`: HTTP keeps one note: `note: body.note.into_iter().collect()`. `crates/engine/src/api.rs` is unchanged.
5. Test (patch): in `crates/cli/tests/features/main.rs`, after the existing `--note` loop, run `edit CS-1 --note y --note z --note y` once and assert exactly one `: y` line and one `: z` line, with `y` before `z`. Catches: only the last note kept, duplicates. Misses: HTTP (unchanged).

## Outcome

stone edit --note repeats: several notes land in one store write, in order, the same text once. Checked: cli features test 3 passed (new case fails with only the last note kept), engine items:: 19 passed.
