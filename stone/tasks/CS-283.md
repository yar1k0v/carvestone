## Description

Agents and people find SQL tables, views and functions with `stone code find`, and `stone code uses <table>` lists the foreign keys and views that point at it. Stone reads the DDL in `.sql` files under the code roots; it never connects to a database (ADR-22).

## Plan

1. Before any edit, run `bash scripts/check.sh size-before cargo build --release --bin stone` and note the byte size of `target/release/stone.exe` for `## Outcome`.
2. `Cargo.toml`: add `sqlparser = { version = "0.64", default-features = false, features = ["visitor"] }` under `[workspace.dependencies]`. `crates/graph/Cargo.toml`: add `sqlparser.workspace = true`. Docs: https://docs.rs/sqlparser/0.64.0/sqlparser/ (`parser::Parser::parse_sql`, `dialect::GenericDialect`, `ast::Spanned`, `ast::visit_relations`).
3. `crates/graph/src/facts.rs#Lang`: add `Sql`; `as_str` returns `"sql"`; `lang_of` maps extension `sql` to `Lang::Sql`. Let the compiler errors list every other match to extend.
4. `crates/graph/src/sql.rs` (new) with `extract_sql(path, src) -> FileFacts` (new):
   - First decl is the `DeclKind::File` decl, built like `crates/graph/src/dart.rs#extract_dart`.
   - Parse the whole text with `GenericDialect`. If that fails, split the text on `;` outside quotes and comments, parse each piece alone, and add one `Warning` per piece that fails, at the piece's first line. Lines of a piece are offset by the lines before it.
   - `CREATE TABLE` and `CREATE VIEW` become `DeclKind::Type`; `CREATE FUNCTION` and `CREATE PROCEDURE` become `DeclKind::Function`, all with `parent: Some(0)`. `name` is the last part of the object name; `qname` is the object name as written, parts joined with `.`, quotes removed. `signature` is the statement's first line, trimmed. Lines come from `Spanned::span()`; a span with line 0 falls back to the piece's lines.
   - Each foreign key (column `REFERENCES` and table `FOREIGN KEY ... REFERENCES`) adds a `RefSite` of `RefKind::References`: `name` the referenced object name as written, `scope` the table decl, `line` the table's start line.
   - Each relation a view's query reads (`visit_relations`) adds the same kind of site, scoped to the view.
   - `ALTER TABLE ... ADD ... FOREIGN KEY` adds the same site, scoped to the file decl.
5. `crates/graph/src/lib.rs#extract`: add `Lang::Sql => sql::extract_sql(path, src)` and `mod sql;`.
6. `crates/graph/src/resolve_sql.rs` (new) with `SqlResolver` (new), returned by `crates/graph/src/resolve.rs#resolver_for` and listed in `LANGS`: a site resolves to every Sql decl of kind Type whose `qname` equals the site name (ASCII case-insensitive); when none does, to every one whose `name` equals the site name's last part. One match gives an exact edge; several give one inferred edge per match; none gives `dst: None` with the name as written.
7. `crates/engine/src/code_index.rs`: `governing_kinds(Lang::Sql)` returns `&[]`; add `Lang::Sql` to `lang_from`. Bump `crates/graph/src/lib.rs#CODE_GRAPH_VERSION` by one.
8. Seam: the split fallback in `extract_sql`. It catches one bad statement hiding the rest of the file; it misses dialect syntax the parser accepts wrongly. Test choice: add (private code with real logic, no test reaches it). In `crates/graph/src/sql.rs` add `#[cfg(test)] mod tests` with one table test: a clean file with two tables gives both qnames and no warning; the same file with `CREATE TABLE ((;` between them gives both qnames and one warning at the bad statement's line.
9. Seam: extract plus resolve across files. It catches a foreign key between two files; it misses views (covered by step 8's table only if you add a view row there). Test choice: patch.
