## Description

Seen on 2026-11-11: `stone edit docs/prd --section "Carvestone — PRD"` with one line of text replaced the level-1 section and all 300 lines of level-2 sections under it. The command said only 'updated docs/prd'. A reader expects the text of that heading to change, not every section below it.

## Plan

Cause, reproduced by the Lead in a throwaway store: `crates/core/src/section.rs#sections` ends a section at the next heading of the same or a higher level, so a section holds every deeper heading under it. `crates/core/src/section.rs#set_section` replaces everything from the heading line to that end. `crates/engine/src/edit.rs#replace_section` calls it from `Repo::edit_if_match` and reports nothing. It is not only level 1: `--section One` on `## One` with a `### Deep` under it drops `### Deep` too.

Decision (owner, in Notes): refuse the edit when the section holds sub-sections the new text does not carry, and name them. `--replace-nested` overrides. New text that carries the same sub-headings passes.

Rule, exact: a sub-section is every entry of `sections(body, 1)` that starts after the found section's `start_line` and ends at or before its `end_line`. The new text carries it when `sections(text, 1)` has an entry whose `title` equals its title under `eq_ignore_ascii_case`; the level is not compared. The check runs on a dry run too. `--section body`, a section that does not exist yet, `--note` and `stone new` are not checked. `set_section` does not change.

Write paths: the CLI (`crates/cli/src/main.rs#run`, arm `Command::Edit`) and HTTP (`crates/server/src/write.rs#patch_item`) both call `Repo::edit` or `Repo::edit_if_match`, so one check in the engine covers both. The MCP tools are read-only and build no `Edit`. The web UI sends no `section` today.

Outside types: `crates/engine/src/edit.rs#Edit`, `crates/engine/src/api.rs#PatchRequest`, `crates/engine/src/repo.rs#EngineError` (variant `Invalid`), `crates/core/src/section.rs#Section`.

1. Seam A: `crates/engine/src/edit.rs#Repo::edit_if_match`. It catches: a dropped sub-section at any level, the override, a rewrite that carries the headings, and a refused edit that still writes. It misses: the clap flag and the HTTP field. Test choice: add `a_section_edit_refuses_to_drop_nested_sections` to `crates/engine/tests/features/items.rs`. Patching is not enough: this is a new write rule, and no existing test has a nested heading (the closest is `an_edit_changes_only_its_lines_and_keeps_crlf`).
2. Add `pub replace_nested: bool` to `Edit`, with the doc comment `/// Replace the section although it holds sub-sections the new text does not carry.`. To compile, add `replace_nested: false` to the `Edit` literals in `run` (arm `Command::Edit`) and in `patch_item`.
3. Red. Write the test as one table. Fixture: `const NESTED: &str = "---\ntype: doc\ntitle: Guide\n---\n\n# Top\n\nIntro.\n\n## One\n\nA.\n\n### Deep\n\nD.\n\n## Two\n\nB.\n";`, written to `stone/docs/guide.md` before each row. Rows (section name, new text, `replace_nested`, expected):
   - `Top`, `New intro.`, false → `Err`; `to_string()` is ``section `Top` holds 3 sub-sections the new text does not carry (One, Deep, Two); edit each by name, or pass --replace-nested to replace them all``; the file equals `NESTED`.
   - `one`, `New A.`, false → `Err`; the sentence starts ``section `One` holds 1 sub-section the new text does not carry (Deep);``; the file equals `NESTED`.
   - `One`, `New A.\n\n### deep\n\nNew D.`, false → `Ok`; the file through `unstamped` equals `NESTED.replace("A.\n\n### Deep\n\nD.", "New A.\n\n### deep\n\nNew D.")`.
   - `One`, `New A.`, true → `Ok`; the file through `unstamped` equals `NESTED.replace("A.\n\n### Deep\n\nD.\n", "New A.\n")`.
   - `Two`, `New B.`, false → `Ok`; the file through `unstamped` equals `NESTED.replace("B.", "New B.")`.
   Also assert once that the first row with `dry_run` true gives the same `Err`. Run criterion 1: rows one and two must fail on their assertions.
4. Green. In `crates/engine/src/edit.rs` add `fn dropped_nested(body: &str, name: &str, text: &str) -> Option<(String, Vec<String>)>`. It finds the section the way `replace_section` does (title under `eq_ignore_ascii_case`, then anchor) and returns the section's title and the titles of its sub-sections the text does not carry, in document order; `None` when the section is missing or the list is empty. Move the shared lookup into one private helper that both functions call.
5. In `Repo::edit_if_match`, inside the `if let Some((name, text)) = &req.section` block and before `replace_section`: when `!req.replace_nested` and `dropped_nested` returns `Some`, return `EngineError::Invalid` with the sentence of step 3 (`1 sub-section` for one, `N sub-sections` for more, titles joined with `, `).
6. Seam B: `crates/cli/src/main.rs#EditArgs`. It catches: the flag missing or not handed on. Test choice: patch `crates/cli/tests/features/main.rs#every_command_answers_on_a_small_store` with the row `(&["edit", "CS-1", "--section", "notes", "--text", "n", "--replace-nested"], 0, "updated CS-1")`, straight after the row `(&["edit", "CS-1", "--set", "priority=high"], 0, "updated CS-1")`. Red: exit 2 before the field exists.
7. Add `replace_nested: bool` to `EditArgs` with `#[arg(long, requires = "section")]` and the doc comment `/// Replace the section although it holds sub-sections the new text does not carry.`. In `run`, arm `Command::Edit`, write `replace_nested: args.replace_nested`.
8. Seam C: `crates/engine/src/api.rs#PatchRequest`. Add `pub replace_nested: bool` with the same two attributes as `dry_run` (`#[serde(default)]` and the `ts(as = "Option<bool>", optional)` line) and the doc comment of step 2. In `patch_item` write `replace_nested: body.replace_nested`. Pass-through of one flag. Test choice: none; criteria 4 and 5 prove it compiles and the type file is current.
9. Run criterion 5. It rewrites `web/src/api/types/PatchRequest.ts`; never edit that file by hand.
10. Run the acceptance commands, then the full checks, with the `web/` checks.
