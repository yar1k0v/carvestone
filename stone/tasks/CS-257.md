## Description

Found in the CS-253 QA pass: crates/engine/src/session_hook.rs#apply rewrites an existing .claude/settings.json with LF endings, against the rule that CRLF stays CRLF. Not planned yet.

## Plan

`crates/engine/src/session_hook.rs#apply` prints the merged settings with `serde_json::to_string_pretty`, which writes LF only. A Windows user's `.claude/settings.json` with CRLF endings comes back with LF endings, against the rule that CRLF stays CRLF. The fix keeps the file's line endings. The two-space reformat on the first add stays (the CS-243 decision).

Rule: when `text` contains `"\r\n"`, every `"\n"` of the output becomes `"\r\n"`. Otherwise the output stays LF. The JSON that `to_string_pretty` prints has no `\r` of its own, so the swap is safe.

The full checks are deferred: the owner runs them once at the end of the session.

1. Seam: `crates/engine/src/session_hook.rs#apply`. It catches CRLF that turns into LF, and a CRLF file that changes on a second run. It misses mixed endings (a file with both counts as CRLF). Test choice: patch `crates/engine/tests/features/workspace.rs#the_session_hook_is_added_once_and_keeps_the_settings`, because it already holds the merge rows. Add two assertions after the `ordered` row:
   - `session_hook::apply("{\r\n  \"env\": {\r\n    \"A\": \"1\"\r\n  }\r\n}\r\n")` equals `format!("{{\r\n  \"env\": {{\r\n    \"A\": \"1\"\r\n  }},\r\n{}\r\n", HOOK_TAIL.replace('\n', "\r\n"))`. The expected value is the known literal `HOOK_TAIL` with CRLF endings.
   - That result given to `apply` again → the same text, byte for byte (the hook is already present).
   Run `cargo test -p carvestone-engine --test features workspace::the_session_hook`: the first new assertion must fail on the assertion (LF output).
2. Green: in `apply`, after `out.push('\n');`, add `if text.contains("\r\n") { out = out.replace('\n', "\r\n"); }`. Comment: why (the user's file keeps its line endings).
3. Update the module doc comment of `crates/engine/src/session_hook.rs` so it also says that the line endings stay.
4. Run the acceptance commands.

## Outcome

apply in session_hook.rs now keeps CRLF in .claude/settings.json (LF files stay LF); a second run changes nothing. Checked by a CRLF case in the session-hook test (red on LF output, then green) and the CLI features tests.
