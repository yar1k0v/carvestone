## Description

The service view names the patterns a service uses, each with a count and example code, marked inferred, in the same four groups for every language: API surface (controllers, minimal APIs, gRPC, MCP endpoints, HTTP routes in Node and Python services), messaging (consumers and producers, for example MassTransit, Kafka, queues), data access (DbContexts, repositories, ORM models, which stores), app structure (handlers, background workers, DI registrations, layers, React apps). One pattern list and one page serve all languages; each language adds its own rules for recognising its frameworks. C# comes first and proves the shape; TypeScript, Python and Dart follow as further rule sets with no change to the page.
