## Description

ci run 42983480256 on the public repo, job test (macos-latest): crates/server/tests/features/main.rs test an_edit_made_outside_shows_on_the_event_stream fails with "no items event within 15 seconds". The same test passes on ubuntu-latest and on the owner's Windows machine. Effect, if the product behaves like the test: `stone serve` on macOS does not refresh the UI after a file changes outside the server. Cause unknown: find it first. Places to look: whether the watcher compares event paths with a root that is not canonical (macOS temp folders sit behind the /var to /private/var link), and whether the first write lands before the watcher is ready. The windows-latest job was cancelled twice by the matrix fail-fast, so its result on the runner is still unknown.

## Plan

Likely cause, found by the Lead in the code and not yet proven on a Mac: `crates/engine/src/changes.rs#repo_relative` strips `repo.store.layout.root` from the event path as written. On macOS the watcher reports real paths (`/private/var/...`), and a temp folder root is written through a link (`/var/...`). The strip fails, every caller in `crates/server/src/watch.rs` gets `None`, and no event goes out. The same happens for a user whose repo path holds a link. Proof is the macOS `ci` job only; there is no Mac here.

1. Seam: `crates/engine/src/changes.rs#repo_relative`. It catches an absolute path under the root as written. It misses a path given through the root's real location. Test choice: none new. The existing `crates/server/tests/features/main.rs` test `an_edit_made_outside_shows_on_the_event_stream` is the red case on macOS (ci run 42983480256), and a link to a folder cannot be made on Windows without extra rights.
2. In `repo_relative`, for an absolute path: first strip `repo.store.layout.root` as now. When that fails, strip `std::fs::canonicalize(&repo.store.layout.root)`. When that fails too, or the root cannot be resolved, return `None` as now. Add a why-comment: the watcher reports real paths, and the root may be written through a link.
3. `.github/workflows/ci.yml`: under `jobs.test.strategy`, add `fail-fast: false`, so one platform's failure does not hide the others.
4. Run the acceptance commands. Do not commit or push; the Lead pushes and reads the `ci` run.
