## Description

Reported from the waypost repo (stone 0.1.0+f7d160c, after stone code native with rust-analyzer: 2857 native edges). stone code uses and stone code impact return no hits for a Rust pub const that the code uses. Types work: stone code uses lookup::Index lists its callers.

Repro in waypost: stone code uses format::FORMAT_VERSION says 'nothing uses format::FORMAT_VERSION', and impact says 'nothing depends on' it. Yet crates/waypost-core/src/format.rs uses it at lines 155, 163, 204 and 216. stone code uses MAX_BATCH returns hits: [] in --json, and crates/waypost-server/src/main.rs uses it at lines 174 and 175. stone code find FORMAT_VERSION does find the symbol (format.rs L28, member).

Effect: impact on a constant understates what a change breaks. waypost's rule 'change a record layout, bump FORMAT_VERSION' cannot be checked with stone. Cause unknown: find it first (the constant has no edges in the graph, same-file uses are dropped, or const reads are not collected).

## Plan

Cause, found by the Lead and reproduced in this repo: `target/debug/stone.exe code uses watch::QUIET` says "nothing uses watch::QUIET", but `crates/server/src/watch.rs#debounce` reads it. `crates/graph/src/rust.rs#walk_sites` emits a `References` site for scoped identifiers, type identifiers, struct expressions, calls and macros. A plain `identifier` in an expression emits nothing, and a const read is a plain identifier. Why the native pass in the waypost report added no edge either is not known yet (step 7).

1. Seam: `crates/graph/src/rust.rs#walk_sites`. It catches paths, types and calls. It misses a const or static read by its bare name. Test choice: patch the fixture `bench/code/rust`, which `crates/engine/tests/bench_code.rs#uses_recall_per_language` scores.
2. Fixture, appended so that existing line numbers stay:
   - `bench/code/rust/src/src/order.rs`: after the last line add a blank line, `pub const LIMIT: u32 = 3;`, a blank line, and `pub fn capped() -> u32 {` / `    LIMIT` / `}`.
   - `bench/code/rust/src/src/checkout.rs`: change line 1 to `use crate::order::{Order, total, LIMIT};`. After the last line add a blank line and `pub fn over(n: u32) -> bool {` / `    n > LIMIT` / `}`.
   - `bench/code/rust/expected_uses.yml`: add `- symbol: order::LIMIT` with sites `src/order.rs:17`, `src/checkout.rs:1` and `src/checkout.rs:10`. Count the lines in the two files yourself and correct the numbers if they differ.
3. Red: `cargo test -p carvestone-engine --test bench_code` must fail for rust. If the recall gate still passes with the new row unmet, stop and write that under `## Notes`.
4. Green, in `walk_sites`: add an arm for the kind `identifier`. When the text has 2 or more characters, starts with an ASCII uppercase letter and holds only ASCII uppercase letters, digits and `_`, call `push_reference(out, name, None, node)`. Return in every case, as the `type_identifier` arm does.
5. In the same function, skip the `name` child of `const_item`, `static_item` and `const_parameter`, the way the `struct_item` arm skips its name. A declaration is not a use of itself.
6. Resolver: expect no change. A bare name with no qualifier takes the path a type identifier takes. If the fixture stays red after steps 4 and 5, find the reason in `crates/graph/src/resolve_rust.rs`, fix it there, and write the cause under `## Notes`.
7. Native pass: after `cargo build --bin stone`, run the two `code uses` commands of the acceptance list, then `target/debug/stone.exe code native`, then the two commands again. The sites must still be listed. If `code native` reports rust-analyzer as skipped, write that under `## Notes` and go on. If the native pass removes the sites, stop and write both outputs under `## Notes`.
8. Run the acceptance commands.
