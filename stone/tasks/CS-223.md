## Description

Reported from the waypost repo (stone 0.1.0+f7d160c, after stone code native with rust-analyzer: 2857 native edges). stone code uses and stone code impact return no hits for a Rust pub const that the code uses. Types work: stone code uses lookup::Index lists its callers.

Repro in waypost: stone code uses format::FORMAT_VERSION says 'nothing uses format::FORMAT_VERSION', and impact says 'nothing depends on' it. Yet crates/waypost-core/src/format.rs uses it at lines 155, 163, 204 and 216. stone code uses MAX_BATCH returns hits: [] in --json, and crates/waypost-server/src/main.rs uses it at lines 174 and 175. stone code find FORMAT_VERSION does find the symbol (format.rs L28, member).

Effect: impact on a constant understates what a change breaks. waypost's rule 'change a record layout, bump FORMAT_VERSION' cannot be checked with stone. Cause unknown: find it first (the constant has no edges in the graph, same-file uses are dropped, or const reads are not collected).
