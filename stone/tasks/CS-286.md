## Description

With `stone hook` wired as a Claude Code PreToolUse hook on Read and Grep, the agent gets a one-line note naming the stone command that answers the same question (`code outline <file>` for a Read of an indexed file, `code find`/`code uses` for a Grep of a known symbol). It never blocks and stone does not edit settings.json (ADR-22).

## Acceptance criteria

- [ ] `bash scripts/check.sh hook-feature cargo test -p carvestone-engine --test features read_hook::` → `1 passed`
- [ ] `bash scripts/check.sh hook-build cargo build --bin stone` → exit 0

## Plan

1. `crates/engine/src/read_hook.rs` (new), declared in `crates/engine/src/lib.rs` as `pub mod read_hook;`, with `advise(repo: &Repo, input: &serde_json::Value, program: &str) -> Option<String>` (new). It reads `tool_name` and `tool_input`:
   - `Read`: take `tool_input.file_path`, replace `\` with `/`, and make it relative to `repo.store.layout.root` (an absolute path outside the root gives `None`). Call `crate::code::outline` with `CodeQuery { target: rel, ..CodeQuery::default() }`. If it returns at least one entry, return `stone indexes <rel>: \`<program> code outline <rel>\` lists its symbols with line ranges; then Read only the range you need.` Otherwise `None`.
   - `Grep`: take `tool_input.pattern`. Only a plain name (ASCII letters, digits, `_`, and `::` or `.` between parts, no other character) goes on. Call `crate::code::find` with that name as target. If it has hits, return `\`<program> code find <name>\` and \`<program> code uses <name>\` answer this from the index.` Otherwise `None`.
   - Any other tool, a missing field or any `Err` from the engine gives `None`: the hook fails open.
2. `crates/cli/src/main.rs#Command`: add `Hook` (new), doc comment `Advise a Claude Code PreToolUse call on Read or Grep: print a note naming the stone command that answers it, or nothing`. The handler reads all of stdin; invalid JSON prints nothing and exits 0. It opens the repo from the current directory (a failure prints nothing, exit 0) and calls `advise` with `program` = the first argument the process got, with `\` replaced by `/`. On `Some(note)` it prints `{"hookSpecificOutput":{"hookEventName":"PreToolUse","additionalContext":<note>}}` built with `serde_json::json!`, one line. It never prints a `permissionDecision`. Hook format: https://code.claude.com/docs/en/hooks (PreToolUse decision control, `additionalContext`).
3. Seam: `advise`. It catches the Read note, the Grep note, unindexed files, files outside the root, regex patterns and other tools; it misses the CLI's stdin and JSON wiring (the acceptance commands cover that). Test choice: add (new public behavior). `crates/engine/tests/features/read_hook.rs` (new), listed in `crates/engine/tests/features/main.rs`: one table test over a store built like `crates/engine/tests/features/code_graph.rs#rust_project` (code under `src/`), `program` `stone`. Rows: Read `src/util.rs` (note names `stone code outline src/util.rs`); Read the same file as an absolute path under the root (same note); Read `README.md` (none); Read an absolute path outside the root (none); Grep `helper` (note names `stone code find helper`); Grep `help.*er` (none); Grep `nothing_here` (none); tool `Bash` (none). Take expected notes from the literal text in step 1.
4. Docs: `target/debug/stone edit docs/feature-agent-surface --section read-hook` (a new `## Read hook` section; check the anchor with `get`) with: what the note says, that it never blocks, and this snippet for `.claude/settings.json`: `{"hooks":{"PreToolUse":[{"matcher":"Read|Grep","hooks":[{"type":"command","command":"stone hook"}]}]}}`.
