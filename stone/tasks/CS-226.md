## Description

First ci run on the public repo (ubuntu-latest): crates/engine/tests/features/workspace.rs test a_repo_git_cannot_read_is_named_and_the_other_still_answers fails. With portal/.git holding 'gitdir: elsewhere', stone check on Linux says 'git rev-parse --git-dir failed: fatal: gitfile does not point to a valid repository: <path>' where the test expects 'git is not available in this folder'. It passes on the owner's Windows machine. The windows and macos jobs were cancelled, so their result on the runners is unknown. Cause not found yet: find where the engine maps the git error text to that sentence first.

## Plan

Cause, found by the Lead: `crates/git/src/lib.rs#is_not_a_repo` matches git's stderr text. For a `.git` file that points nowhere, git on the Linux runner prints `fatal: gitfile does not point to a valid repository: <path>`. That text matches neither pattern, so the call returns `GitError::Command` with the raw text, not `GitError::Unavailable`.

1. Seam: `crates/git/src/lib.rs#is_not_a_repo`. It catches the git wordings for "this folder has no usable repository". It misses wordings of other git versions and translated git output. Test choice: add. No existing test can reach the Linux wording on Windows; `crates/engine/tests/features/workspace.rs` reaches it on Linux only.
2. Red: add a `#[cfg(test)] mod tests` at the end of `crates/git/src/lib.rs` with one table test `not_a_repo_wordings`. Rows, each a stderr literal and the expected bool: `fatal: not a git repository (or any of the parent directories): .git` → true; `fatal: cannot change to 'portal': No such file or directory` → true; `fatal: gitfile does not point to a valid repository: /tmp/x/portal/.git` → true; `fatal: bad revision 'nope'` → false. Run it: the third row must fail.
3. Green: in `is_not_a_repo`, also return true when stderr contains `does not point to a valid repository`.
4. Change nothing in `crates/engine/tests/features/workspace.rs`: its expected sentence is right.
5. Run the acceptance commands.
