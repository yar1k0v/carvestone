## Description

Agents grouping tasks by feature read every task file because stone list rows lack components and links, and stone list --json dumps changed_files. Rows gain components and links; --status takes a comma list; --open hides done and archived items; --json adds changed_files only with --changed-files. CLI and MCP list.

## Acceptance criteria

- [x] `cargo test -p carvestone-engine --test features tasks::` → all pass, the `N passed` line counts list_filters_status_lists_and_open
- [x] `cargo test -p carvestone-mcp --test features tools::` → all pass, N passed > 0
- [x] `cargo test -p carvestone-engine --features ts ts_export` then `git diff --stat web/src/api/types` → only ListRow.ts changed
- [x] `target/debug/stone list --type task --open` → no done or archived rows; rows with components end in [..]
- [x] `target/debug/stone list --type task --status todo,review --json` → rows carry components, no changed_files key

## Plan

1. `crates/engine/src/query.rs#ListRow`: add `components: Vec<String>` and `links: Vec<String>`, both copied from the item's front matter (`crates/core/src/item.rs#Fields`), `skip_serializing_if = "Vec::is_empty"` and the same `ts` attributes as `depends_on`. Fill them in `crates/engine/src/query.rs#Repo::list` for every item type.
2. `crates/engine/src/query.rs#ListFilter`: add `open: bool` with a doc line: only items whose status is not `done` or `archived`; an item without a status stays in. In `Repo::list`, `status` now holds a comma list: split on `,`, trim, drop empty parts; a row passes when its status equals any part. Skip a row with `open` set and status `done` or `archived`.
3. `crates/cli/src/main.rs#ListArgs`: document `--status` as "one status or a comma list, e.g. todo,review"; add `--open` (bool, doc: "Only items not done or archived") and `--changed-files` (bool, doc: "With --json: add the paths each task changed (reads git history)"). In `Command::List` pass `open: args.open` and set `changed_files: cli.json && args.changed_files`. JSON no longer carries `changed_files` by default: a deliberate behavior change.
4. `crates/cli/src/lean.rs#list_lines`: after the title, add `  [<components joined by ", ">]` when the row has components. Links stay JSON only.
5. `crates/mcp/src/tools.rs#ListArgs`: add `open: Option<bool>` (doc as in step 2); `list_tool` passes `open: args.open == Some(true)`. Extend the `ready` refusal so `open` cannot be combined with `ready` either. The `status` doc says it takes a comma list.
6. `crates/server/src/routes.rs#list_items`: add `open: false` to its `ListFilter` literal only (no new query param).
7. Regenerate `web/src/api/types/ListRow.ts` through the checker: `cargo test -p carvestone-engine --features ts ts_export`.

Tests (Patch, `crates/engine/tests/features/tasks.rs#list_rows_carry_what_a_board_card_shows`): add `links: [docs/x]` to CS-1 and assert `components` and `links` in `facts` (CS-2 gives empty vecs). Catches a field not filled; misses CLI text.
Tests (Add, `crates/engine/tests/features/tasks.rs#list_filters_status_lists_and_open` (new)): one table over tasks with status todo, review, done, archived and one without status: `status: "todo,review"` gives the todo and review rows; `status: "todo, ,review"` the same; `open: true` gives todo, review and the no-status task; `open` with `status: "done"` gives none. Catches split and open rules; misses MCP wiring (smoke via `crates/mcp/tests/features/tools.rs#list_filters_by_field_and_ready_gives_the_tasks_whose_dependencies_are_done`: patch one row with `open: true` combined with `ready: true` expecting the refusal).
