## Description

Before stone loads grammars on demand as WebAssembly files, the owner learns what it costs: the binary size wasmtime adds against the native C# grammar it replaces, and the parse speed. Trial only, off by default; nothing changes for users.

## Acceptance criteria

- [x] `bash scripts/check.sh probe-native cargo build --release -p carvestone-graph --example wasm_probe` → exit 0
- [x] `bash scripts/check.sh probe-wasm cargo build --release -p carvestone-graph --example wasm_probe --features wasm-grammars --target-dir target/wasm-trial` → exit 0
- [x] `target/wasm-trial/release/examples/wasm_probe docs/agent-scratch/wasm/tree-sitter-c_sharp.wasm bench/code/csharp/src/Shop/OrderService.cs` → prints `mode wasm`, a root kind `compilation_unit` and a node count
- [x] `target/release/examples/wasm_probe - bench/code/csharp/src/Shop/OrderService.cs` → prints `mode native` and the same node count as the wasm run
- [x] `## Outcome` holds both example sizes, their difference, the .wasm file size and both parse times

## Plan

1. `crates/graph/Cargo.toml`: add `[features]` with `wasm-grammars = ["tree-sitter/wasm"]`. Docs: https://docs.rs/tree-sitter/0.26.0/tree_sitter/struct.WasmStore.html (`WasmStore::new(&wasmtime::Engine)`, `load_language(name, bytes)`, then `Parser::set_wasm_store`). Use the `wasmtime` engine type that tree-sitter re-exports, or add `wasmtime` with the exact version tree-sitter 0.26 requires (36.x) under the same feature.
2. `crates/graph/examples/wasm_probe.rs` (new): `wasm_probe <WASM|-> <SOURCE>`. Add `#![allow(clippy::print_stdout)]` at the top. With feature `wasm-grammars`: read the .wasm, `WasmStore::load_language("c_sharp", bytes)`, parse SOURCE, print `mode wasm`, the root node kind, the total node count (walk with `TreeCursor`) and the parse time in ms (`std::time::Instant`, best of 20 runs). Without the feature: the same with `tree_sitter_c_sharp::LANGUAGE`, printing `mode native`. With the feature on, the example must not name `tree_sitter_c_sharp` or any `carvestone_graph` function, so the linker drops the native C# tables.
3. Get the grammar: download `tree-sitter-c_sharp.wasm` from the tree-sitter-c-sharp GitHub release that matches the crate version in `Cargo.toml` (0.23.x) into `docs/agent-scratch/wasm/` (git-ignored). If that release has no .wasm asset, stop and report. Do not install emscripten.
4. Run the acceptance commands with nothing else compiling (timing). Read file sizes of `target/release/examples/wasm_probe(.exe)` and `target/wasm-trial/release/examples/wasm_probe(.exe)`.
5. Write `## Outcome`: native size, wasm size, difference (wasm minus native = wasmtime cost minus the C# tables), .wasm file size, best parse time for each mode, and whether node counts match. Delete `target/wasm-trial` afterwards.
6. Test: none (trial; the example is the probe, and the feature is off by default).

## Outcome

Release example sizes: native 5,581,312 bytes, wasm 10,450,944 bytes, difference +4,869,632 bytes (about 4.64 MiB; wasmtime cost minus the native C# tables). The .wasm grammar is 5,350,581 bytes (tree-sitter-c-sharp v0.23.5 release). Best parse of bench/code/csharp/src/Shop/OrderService.cs over 20 runs: native 0.021 ms, wasm 0.053 ms (about 2.5x slower; the file is small, 37 nodes). Node counts match: 37 in both modes, root compilation_unit. Feature wasm-grammars is off by default.
