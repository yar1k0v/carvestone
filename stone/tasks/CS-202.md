## Plan

Built on CS-232 (`depends_on`): the engine returns the brief as `crates/engine/src/tiers.rs#Part` values and the CLI cuts them with `crates/engine/src/tiers.rs#fit`. The engine builds the lines, as `crates/engine/src/precedents.rs#Precedents::lines` does, so an MCP tool can reuse the brief later. Not in scope: an MCP tool, the agent guide, the ready check, and the before/after measurement on the debug guide (the Lead runs it after acceptance).

The parts, in print order. The first two are critical (owner's decision in CS-232 Notes); all others are optional and shrink by the CS-232 rule:

| Part name | Tier | Heading | Lines |
| --- | --- | --- | --- |
| `task` | critical | none | `<label>  <title>  <status>`; then the text of the sections `description`, `acceptance-criteria` and `plan`, each with its heading line and without trailing blank lines, or the line `(no ## <Title> section)` for a missing one; then `Paths: a, b` when `paths` is not empty; then `Depends on: X, Y` when `depends_on` is not empty |
| `links` | critical | `Links:` | one pointer line per linked item: `<label>  <title>  about <t> tokens`, where `t` is `tiers::tokens` of the item's body; a target that does not resolve prints `<target>  not found; run stone check`. No part when the task links nothing |
| `<label>#<anchor>` | optional | `<label>#<anchor>:` | the text of one linked section without its heading line. One part per linked section |
| `entry points` | optional | `Entry points:` | for each id in `components`: the entry rows of that component; `<id>: none found` when it has none; `<id>: not available: <error>` when the lookup fails |
| `outline <path>` | optional | `<path>` | one part per entry of `paths`: the outline lines of the file; when the lookup fails the part has no heading and the one line `<path>: no outline: <error>` |
| `precedents` | optional | `Precedents:` | up to three precedent lines; `not available: <error>` when the lookup fails; no part when there are none |

Linked items: the rows of `crates/engine/src/links.rs#links_of` for the task whose `kind` is `links`, `components` or `wikilink`, in file order, the first row per target item kept; the task itself is skipped. Linked sections: a row with an anchor gives that section; a row without an anchor gives the target's `decision` section when the target has one (so a linked ADR shows its decision), and nothing otherwise. Architecture items give no section part; their code comes through `entry points`.
