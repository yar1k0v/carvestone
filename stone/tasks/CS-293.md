## Description

For a doc, decision, plan or architecture item, `stone brief` lists a finished task only when its title shares a word with the item's title or `description` field. Sharing a component is no longer enough. An agent asking about a feature no longer gets unrelated work on the same component, such as a README fix.

## Plan

1. In `crates/engine/src/precedents.rs`, make `STOP_WORDS` and `title_words` `pub(crate)`. No other change there.
2. In `crates/engine/src/brief.rs`, add `fn item_words(item: &carvestone_core::Item) -> BTreeSet<String>` (new): the words of the title plus the `description` field, split on non-alphanumeric chars, lowercased, at least 4 chars, not in `STOP_WORDS`, each passed through `stem`.
3. Add `fn stem(word: &str) -> String` (new): a word of 5 or more chars that ends in `s` loses that `s` (`violations` → `violation`); else the word unchanged.
4. Add `fn by_words(words: &BTreeSet<String>, found: Vec<(Precedent, BTreeSet<String>)>) -> Vec<Precedent>` (new): keep a precedent only when its stemmed title words share at least one word with `words`; push `words <up to 3 shared, sorted>` to its `matched`; sort by shared count, most first, keeping the input order on ties (stable sort).
5. In `item_brief`, in the finished-tasks step: ask `precedents` per component with `limit: Some(FINISHED_CANDIDATES)` (new const, 50) instead of `PRECEDENTS_SHOWN_ITEM`; collect each hit with the stemmed `title_words` of its task (resolve `hit.id` in the snapshot); merge by id as now; pass the list through `by_words(&item_words(item), ..)`; then skip ids in `linked from` and keep the first `PRECEDENTS_SHOWN_ITEM`. No part when none is left.
6. Test (add) a `#[cfg(test)] mod tests` in `crates/engine/src/brief.rs` with one table test `by_words_keeps_only_tasks_that_share_a_word`: rows (a) words `{violation}`, task titled `Violation rules for night driving` kept with `words violation`; (b) task `portal README uses port 3001` dropped; (c) two kept tasks, the one with 2 shared words first; (d) `stem`: `violations`→`violation`, `rules`→`rule`, `uses`→`uses` (4 chars), `bus`→`bus`. Expected values are literals. Why add: the engine feature tests have no git history, so precedents return no hits there; the filter is private logic with real branches.
