## Description

`stone get <id> --budget N`, `stone arch hld --budget N` and `stone instructions --budget N` fail with 'unexpected argument'. `search`, `precedents` and `code explain` accept it. The baseline in M-18 counts 13 failed calls of this kind, 11 on get.

- [ ] `cargo test -p carvestone-cli --test output_cost typical_calls` → `1 passed` (output without `--budget` did not grow)
- [ ] `cargo test -p carvestone-cli --test features every_command_answers` → `1 passed`
- [ ] After `cargo build --bin stone`: `target/debug/stone.exe get CS-226 --budget 100` → exit 0, at most 400 characters, and the last line ends with `; raise --budget`

- [ ] `target/debug/stone.exe get CS-226 --budget 100 --json` → exit 0 and the whole JSON, with no `left out` line
- [ ] `cargo clippy --workspace --all-targets -- -D warnings` → exit 0

## Plan

Cause, reproduced by the Lead: in `crates/cli/src/main.rs` the variants `Command::Get`, `Command::History`, `Command::Timeline`, `Command::Instructions`, the struct `ListArgs` and the variants `ArchCommand::Hld`, `ArchCommand::Lld`, `ArchCommand::Gaps` and `ArchCommand::C4` have no `budget` field, so clap answers `unexpected argument '--budget'` (exit 2). `search`, `why`, `precedents` and every `code` command already take it.

Scope: the read commands the CLI component names: `get`, `list`, `instructions`, `arch hld`, `arch lld`, `arch gaps`, `arch c4`, `history`, `timeline`. Not in scope: `check`, `task next`, `scan`, `map`, `arch connect`. The cut is by whole lines of the printed text, first lines kept. `--json` output is never cut. Tiers that protect a task's criteria and plan belong to CS-232, not here.

Outside names: `crates/cli/src/lean.rs#fit`, `crates/cli/src/lean.rs#tokens`.

1. Seam: `crates/cli/src/lean.rs`, a new function `fit_lines`. It catches: a refused flag, output over the budget, a missing cut-off line. It misses: nothing the smoke rows of step 5 do not reach. Test choice: patch `crates/cli/tests/output_cost.rs#budget_output_stays_within_the_budget`.
2. Add the stub `pub fn fit_lines(budget: Option<usize>, text: &str) -> String` to `crates/cli/src/lean.rs`, under `fit`. The stub ignores `budget` and returns `text.to_string()`.
3. Add the field `budget: Option<usize>` with `#[arg(long)]` and the doc comment `/// Cut the answer to about this many tokens (chars / 4); whole lines, first lines kept.` to `Command::Get`, `Command::History`, `Command::Timeline`, `Command::Instructions` and `ListArgs`. Turn `ArchCommand::Hld` and `ArchCommand::Gaps` into struct variants that hold only that field, and add the field to `ArchCommand::Lld` and `ArchCommand::C4`.
4. Wire every site in `crates/cli/src/main.rs`. A site passes `None` when `--json` is set, and the flag's value otherwise.
   - `run`, the early `Command::Instructions` block: bind `budget` and print `lean::fit_lines(*budget, &instructions(topic.as_deref(), &start)?)`. The guide is always text, so no `--json` test here. `--write` ignores the budget.
   - `run`, arm `Command::Get`: print `lean::fit_lines(budget, &render_get(...)?)`.
   - `run`, arm `Command::List`: wrap the `render_rows(...)` text; leave the `no items match` line alone.
   - `run`, arm `Command::History`: wrap `found.text()`.
   - `run`, arm `Command::Timeline`: wrap the `render_timeline(...)` text.
   - `run_arch`: match `ArchCommand::Hld { budget }`, `Lld { container, budget }`, `Gaps { budget }` and `C4 { level, id, budget }`, and wrap the text branch of each (`render_hld`, `render_lld`, `render_gaps`, `source`). The `json` branches stay as they are.
5. Red. In `budget_output_stays_within_the_budget` change the `calls` array to 11 entries by adding `&["get", "CS-1"]`, `&["get", "docs/ledger-1"]`, `&["list"]`, `&["arch", "hld"]`, `&["instructions"]`, `&["history", "CS-1"]` and `&["timeline"]`. After the loop add one assertion: the output of `repo.run(&["get", "CS-1", "--budget", "50"])` has exit code 0 and its last line ends with `; raise --budget`. In `crates/cli/tests/features/main.rs#every_command_answers_on_a_small_store` add the row `(&["arch", "lld", "arch/api", "--budget", "400"], 0, "LLD arch/api  Api")` after the `arch lld` row. Run criterion 1: it must fail on `printed N tokens`, not on an exit code.
6. Green. Write `fit_lines`: `None` returns `text.to_string()`. Otherwise collect `text.lines()` and call `fit(budget, lines.len(), render)`, where `render(kept)` gives the first `kept` lines, each with `\n`, and, when `kept` is less than the line count, one last line. That line is `{n} more lines left out, about {t} tokens; raise --budget` (`1 more line left out, ...` for one), where `n` is the count of dropped lines and `t` is `tokens` of the dropped lines joined with `\n`. `fit` keeps one line at least. Doc comment: say that it cuts printed text by whole lines and names the size of what it left out.
7. `arch gaps` and `arch c4`: the flag is one clap field and the cut is the shared `fit_lines`. Test choice: none; criterion 5 runs both on this repo.
8. Run the acceptance commands, then the full checks.
