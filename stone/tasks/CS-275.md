## Description

A release binary built with the web UI stores each embedded file compressed, so the 7.3 MB `web/dist` takes less space in the binary. The server still sends each file unchanged.

## Acceptance criteria

- [x] `pnpm --dir web build` → exit 0
- [x] `bash scripts/check.sh server-ui cargo test -p carvestone-server --features ui` → all pass
- [x] `bash scripts/check.sh release-ui cargo build --release --bin stone --features ui` → exit 0
- [x] `node -e "console.log((require('fs').statSync(process.platform==='win32'?'target/release/stone.exe':'target/release/stone').size/1048576).toFixed(1))"` → less than the size CS-274 recorded in its Outcome

## Plan

1. Build after CS-274, so its Outcome holds the size before this change.
2. `Cargo.toml` `[workspace.dependencies]`: change `rust-embed` features to `["mime-guess", "compression"]`. Docs: https://docs.rs/crate/rust-embed/8.14.0 (feature `compression`: each file is compressed with include-flate when embedded and decompressed on `get`). `crates/server/src/ui.rs#page` stays as is: `file.data` is the original bytes.
3. Write the new binary size and the saving in `## Outcome`.
4. Test: none. The existing `carvestone-server` tests with `--features ui` catch a file that no longer serves.

## Outcome

rust-embed now uses the compression feature (Cargo.toml; Cargo.lock updated to rust-embed 8.14.0 because 8.13.0 needed a libflate version the lock could not resolve). Release binary with ui: 32.7 MiB to 29.1 MiB (34,274,304 B to 30,533,120 B), saving 3.6 MiB. Checked: pnpm build exit 0, carvestone-server tests with ui 5 passed, release build exit 0.
