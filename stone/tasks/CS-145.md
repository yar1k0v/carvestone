## Plan

1. In `web/src/components/planning/progress.ts`, add `type MilestoneState = "Planned" | "Running" | "Closing" | "Paused" | "Done"` and `milestoneState(tasks: ListRow[])`. Use `toneOf` from `web/src/components/ui/status.tsx`. Finished is tone done or archived. Moving is tone progress or review. Waiting is any other open task. First match wins: no tasks → Planned; nothing open → Done; nothing waiting → Closing; something moving → Running; some task finished → Paused; else Planned.
2. Add `web/src/components/planning/progress.test.ts` with one table test for `milestoneState`, using literal rows as (ready, running, review, done): (0, 1, 1, 39) → Closing; (19, 3, 1, 6) → Running; (7, 0, 0, 15) → Paused; (3, 0, 0, 0) → Planned; no tasks → Planned; (0, 0, 0, 4) → Done. It catches a wrong rule order. It misses rendering, which the board criterion covers. Test choice: add, because this is new public behavior with real branches.
3. In `web/src/components/ui/status.tsx`, add to `TONES`: `running` → progress, `closing` → done, `paused` → todo, `planned` → todo.
4. In `web/src/components/planning/MilestoneList.tsx`, render a table with the board columns Milestone, State, Ready, Running, Review, Done, Progress. Fill the counts from `tally`, where Ready is `waiting`. Progress is a bar plus a percent. Remove the target column and its `useItemQuery` call, because the board has neither. Keep the blocked `Flag` beside the name. Replace `OVER` with `milestoneState(tasks) !== "Done"`, and sort by the order Running, Closing, Paused, Planned, Done. Set the description to "Where the work stands. State comes from the tasks, so it cannot go stale."
