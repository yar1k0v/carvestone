## Description

A project lists SCIP index files with their language and file extensions. Stone indexes those files and reads the indexes in code native. Config holds no command to run. The next task creates the symbols.

## Acceptance criteria

- [x] `cargo test -p carvestone-store` → exits 0, `0 failed`, and the new table test passes
- [x] `cargo test -p carvestone-engine` → exits 0, `0 failed`
- [x] `cargo clippy --workspace --all-targets -- -D warnings` → exits 0

## Plan

Format, under the project config. Paths are relative to the root. There is no command field, by ADR-17.

```yaml
scip_indexes:
  - file: .scip/java.scip
    language: java
    extensions: [java, kt]
```

1. In `crates/store/src/config.rs`, add `pub struct ScipIndexEntry { file: String, language: String, extensions: Vec<String> }` and `Config::scip_indexes: Vec<ScipIndexEntry>`, default empty. Parse it in `Config::parse`. Each entry needs all three keys, `extensions` must not be empty, and an extension has no dot. Refuse an unknown key, so a `command` key fails. Do not check against built-in languages: store has no graph dependency, and the `lang_of` branch in `candidates` runs first, so a built-in parser wins for an overlapping extension.
2. Test choice: add. A new saved format. Create `crates/store/tests/config.rs` with one table test of wrong input through `Config::parse`: missing key, empty `extensions`, an extension with a dot, a `command` key, plus one valid row. It catches a config that silently does nothing or runs something. It misses reading the files.
3. In `crates/engine/src/code_index.rs`, add `Kind::Scip(String)` to `Kind`, holding the language. In `candidates`, after the `lang_of` branch, give a path under a code root whose extension an entry lists `Kind::Scip(language)`. In `code_langs`, return nothing for it. In the parse step, it gets one file symbol and no declarations, the same as a code file with no declarations. Store the language in `files.lang`.
4. In `crates/engine/src/code_native.rs#native_with`, when `q.indexes` is empty, also read each `scip_indexes` file as a `Source`, the same way as the `q.indexes` branch. A missing file is a warning line in the report, not an error: `<file> not found; run your indexer first`.
5. Add `scip_indexes` to the config reference in `crates/engine/src/guide/overview.md`, in one line, saying that a built-in parser wins for an extension it reads.
6. Run `cargo build --bin stone`, then the acceptance commands. Symbols for these files come in the next task.
