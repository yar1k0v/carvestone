## Description

After a stone upgrade rebuilds the code index, the links found by the compilers (stone code native) are dropped, so stone code uses misses callers until the owner reruns stone code native, about 6 minutes on Freightline. Keep the native index outputs after they are read and read them again after a rebuild, so the links come back in seconds without a rerun. Done when, after an upgrade that rebuilds the index, stone code uses on Freightline lists the same callers as before the upgrade with no manual step.

## Acceptance criteria

## Outcome

A native pass keeps the indexes it read under .stone/native, with the content hash of every file they matched. When the code index is rebuilt (a new version of stone, a new index format), the next refresh reads them again: on Freightline the rebuild and restore took 13s, no file read as out of date, and the sampled links stayed exact. A file edited between the native pass and the rebuild stays out of date, as after any edit. Indexes made before this change were not kept, so the first upgrade still needs one native run.
