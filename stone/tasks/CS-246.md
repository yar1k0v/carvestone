## Description

A `stone edit --section <name> --text` whose text starts with the section's own heading (`## Outcome` for `outcome`) writes the heading twice, because Stone keeps the heading and replaces only the body. No command removes the extra heading afterwards, and it cost two review rounds and a leftover heading in a finished task. The edit now refuses such a text and names the fix: send the body only. The CLI, MCP and server all go through the same engine edit, so one check covers them.

## Plan

The check sits in `crates/engine/src/edit.rs#Repo::edit_if_match`, in the `req.section` block, before the `dropped_nested` check. `crates/engine/src/edit.rs#find_section` already finds a section by title or anchor. `crates/engine/src/edit.rs#replace_section` stays as it is.

1. Seam: a refusal for a text whose first non-blank line is a heading with the section title. It catches `## Outcome` sent to `outcome`, in any case and at any heading level. It misses a heading in the middle of the text (a deliberate new sub-section) and a heading inside a code fence; both stay allowed. Test choice: add, because the closest test, `crates/engine/tests/features/items.rs#a_section_edit_refuses_to_drop_nested_sections`, has another fixture and another rule.
2. `crates/engine/tests/features/items.rs`: add the test `a_section_edit_refuses_a_text_that_repeats_the_heading`, after `a_section_edit_refuses_to_drop_nested_sections`. It writes the const `TASK` to `stone/tasks/CS-1.md` and calls `repo.edit("CS-1", &section(name, text), false)`. One table of rows `(what, section name, text, refused)`:
   - `("the heading as sent", "description", "## Description\n\nNew.", true)`
   - `("another case and level", "description", "# description\n\nNew.", true)`
   - `("after a blank line", "description", "\n\n## Description\n\nNew.", true)`
   - `("found by anchor", "notes", "## Notes\n\nNew.", true)`
   - `("a different heading", "description", "## Other\n\nNew.", false)`
   - `("a sub-heading in the middle", "description", "New.\n\n### Description\n\nMore.", false)`
   - `("plain text", "description", "New.", false)`
   For a refused row: the error text contains `starts with its own heading`, and `store.read("stone/tasks/CS-1.md")` still equals `TASK`. For an allowed row: the call is `Ok`, then the file is written back to `TASK` with `store.write` before the next row. Run the test: it must fail, because the refusal does not exist yet.
3. `crates/engine/src/edit.rs`: add `fn repeated_heading(body: &str, name: &str, text: &str) -> Option<(String, String)>` after `dropped_nested`. It takes the first line of `text` that is not blank. When that line starts with 1 to 6 `#` characters followed by a space, its title is the rest of the line, trimmed. It returns `(section title, that line trimmed)` when the title equals, ignoring ASCII case, either `name` trimmed or the title of `find_section(&sections(body, 1), name)`. The section title in the result is the found section's title, else `name` trimmed. Otherwise `None`. Add a doc comment that says why: Stone keeps the heading, so a heading in the text is written twice.
4. `crates/engine/src/edit.rs#Repo::edit_if_match`: in the `if let Some((name, text)) = &req.section` block, before the `dropped_nested` check, add: when `repeated_heading(&doc.body, name, text)` is `Some((section, line))`, return `Err(EngineError::Invalid(format!("the text for section `{section}` starts with its own heading `{line}`; Stone keeps the heading, so send the body only")))`. The check runs even with `replace_nested`.
5. Run the test of step 2: it must pass. Then the second and third acceptance commands after `cargo build --bin stone`, then the full checks.
6. Do not run the dry-run commands against another item. Both commands name CS-246 and write nothing.
