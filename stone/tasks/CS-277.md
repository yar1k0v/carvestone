## Description

After a merge with conflicts, `stone check` names each unresolved conflict with its file and line, and `stone resolve <path> --take ours|theirs` settles every conflict in that file.

## Acceptance criteria

- [x] `bash scripts/check.sh merge cargo test -p carvestone-engine --test features merge::` → 4 passed
- [x] `bash scripts/check.sh cli-build cargo build --bin stone` → exit 0
- [x] `target/debug/stone resolve --help` → prints usage with PATH and `--take`
- [x] `target/debug/stone check` → no new problems

## Plan

1. Build after CS-272. `crates/engine/src/merge.rs` and `crates/engine/tests/features/merge.rs` come from CS-272.
2. `crates/engine/src/merge.rs#Side` (new): `pub enum Side { Ours, Theirs }`. `crates/engine/src/merge.rs#take_side` (new): `pub fn take_side(text: &str, side: Side) -> Option<String>`. Replace each block from a `<<<<<<< ` line through its `>>>>>>> ` line with the lines of the chosen side. `None` when the text has no marker line. Keep line endings.
3. `crates/engine/src/merge.rs#conflict_lines` (new): `pub fn conflict_lines(text: &str) -> Vec<usize>`, the 1-based line of each `<<<<<<<` line (exactly seven `<`, then a space or the line end) outside a fence. Add `crates/core/src/section.rs#fence_lines` (new): `pub fn fence_lines(body: &str) -> Vec<bool>`, built on `scan`, true for lines inside a fence.
4. `crates/engine/src/check_files.rs#file_problems`: replace the `marker_line` call with `crate::merge::conflict_lines`, pushing one `conflict` problem per returned line with the message "unresolved merge conflict: run `stone resolve <path> --take ours` or `--take theirs`, or edit the two versions into one". Delete the private helper `marker_line` in the same file. This rule already covers items and reserved files, so `check.rs` does not change.
5. `crates/cli/src/main.rs#Command::Resolve` (new): `stone resolve <PATH> --take <ours|theirs>`. Refuse a path outside `stone/`. Take `Store::lock`, read the file, call `take_side`, write with `write_atomic`, print `resolved <n> conflicts in <PATH>`. When `take_side` returns `None`, print `✗ <PATH> has no conflict` and exit 1.
6. Test: patch `crates/engine/tests/features/merge.rs` with test `take_side_table`: rows for ours, theirs, two blocks in one file, no markers (`None`), CRLF kept. Add test `check_reports_conflict`: a task file with a marker inside a fence at line 7 and one real marker block at line 10 gives exactly one `conflict` problem, at line 10, and none after `take_side` writes it back. Expected values are literals.
