## Description

Stone writes `created` and `generated.at` as `YYYY-MM-DDThh:mm:ss+00:00`, the form OKF v0.2 section 5 asks for, on every new write: `stone new`, `stone edit`, `stone arch connect` and `stone scan`. Existing plain dates stay as they are. `closed` and the dates on Notes lines stay plain days. Stone writes no `verified` stamp today, so no writer of `verified.at` changes. Runs after CS-235 (readers) and CS-188 (the date rule).

## Plan

The readers already accept the new form (CS-235), and `crates/engine/src/fields.rs#set_scalar` accepts it for `created` (CS-188). `crates/store/src/frontmatter.rs#emit_string` puts a value with a colon in single quotes inside `{ .. }`, so `Document::set` writes `generated: { by: <actor>, at: '2026-11-11T10:03:22+00:00' }` with no change in the store crate. Stone has only UTC time, so the offset is always `+00:00`.

1. In `crates/engine/src/create.rs`, add `pub fn timestamp_of(secs: u64) -> String` with the doc comment "A Unix time as `YYYY-MM-DDThh:mm:ss+00:00`, in UTC." It returns `date_of(secs)`, then `T`, then the hour, minute and second of `secs % 86_400`, two digits each with `:` between, then `+00:00`. Add `pub fn now() -> String` beside `#today`, with the doc comment "The UTC time now, in the form new writes use.", reading the clock the way `today` does and returning `timestamp_of`. Keep `today` and `date_of` unchanged.
2. `crates/engine/src/new_item.rs#build_text`: `let created = now();`. The same value goes to `created` and to the `generated` stamp, as today. Import `now` in place of `today`.
3. `crates/engine/src/edit.rs#edit_if_match`: the `generated` stamp takes `&now()`. The `add_note` call keeps `&today()`, so a Notes line keeps a plain day. Import both.
4. `crates/engine/src/edit_tasks.rs#connect`: the `generated` stamp takes `&now()`. Import `now` in place of `today`.
5. `crates/engine/src/scan.rs#scan`: `let today = now();`, and import `now` in place of `today`. A draft that exists keeps its own `created`, as today, so old drafts do not change.
6. `crates/engine/src/scan.rs#render` writes the stamp by hand, and a colon needs quotes inside `{ .. }`. Before the `format!`, add `let at = if date.contains(':') { format!("'{date}'") } else { date.to_string() };` and write `at: {at}` in the template in place of `at: {date}`. `created: {date}` stays plain. A draft with a plain day renders the same text as before, so a second scan still writes nothing.
7. Do not change `crates/engine/src/fields.rs#sync_closed`, `crates/engine/src/edit_tasks.rs#fill_closed` or `crates/engine/src/work_links.rs`: `closed` stays a plain day.
8. Seam: the saved form. Test choice: add, because it is a saved format and no test reaches the clock value. In `crates/engine/tests/features/items.rs`, add `a_timestamp_is_utc_with_an_offset`, one table over `carvestone_engine::create::timestamp_of`: `0` → `1970-01-01T00:00:00+00:00`, `951868799` → `2000-02-29T23:59:59+00:00`, `1794391402` → `2026-11-11T10:03:22+00:00`. It catches a wrong hour, minute or second and a lost leap day. Red: write the signature first with a body that returns `date_of(secs)`.
9. Seam: `stone new`. Test choice: patch `each_type_gets_its_id_and_folder` in the same file. For each created file, take the value `t` of the line that starts with `created: `, and assert: `t.len() == 25`, `t.as_bytes()[10] == b'T'`, `t.ends_with("+00:00")`, and the text contains `at: '<t>' }`. It catches a `created` and a stamp that disagree, and an unquoted stamp.
10. Seam: `stone edit`. Test choice: patch `an_edit_changes_only_its_lines_and_keeps_crlf` in the same file: after the section edit, assert that the file has a line that starts with `generated: ` and contains `+00:00' }`. Then repeat the same section edit and assert the file is unchanged, so a repeat does not stamp a new second.
11. Seam: `stone arch connect`. Test choice: patch `connect_writes_the_uses_entry_and_the_bullet_and_a_repeat_changes_nothing` in `crates/engine/tests/features/architecture.rs`: beside the `"\ngenerated:"` assertion, assert that `text` contains `+00:00' }`.
12. Seam: `stone scan`. Test choice: patch `scan_writes_a_draft_for_code_no_component_owns` in the same file: take the value `t` of the draft's `created: ` line, assert the three shape facts of step 9, and assert the text contains `generated: { by: 'process:stone-scan', at: '<t>' }`. Its existing second-scan assertions prove that the new form reads back and a repeat writes nothing.
13. Seam: what stays plain. Test choice: patch `crates/engine/tests/features/tasks.rs`. Beside the `"\nclosed: 20"` assertion, assert that the `closed: ` line is 18 characters long. `a_note_lands_under_notes_once` already proves that a Notes line carries `create::today()`; leave it.
14. Red first for steps 9 to 12: add the assertions before steps 2 to 6 and see each fail.
