## Description

Mobile apps in Flutter show as boxes only. Read Dart code into the index so a Flutter service gets the same view as the others.

## Acceptance criteria

- [x] Dart files are indexed: stone code find, outline, uses and deps work on a Flutter repo, with packages resolved from pubspec.yaml.
- [x] HTTP calls from a Flutter app (http, dio) appear as requests links to the backend endpoints they hit, so the mobile app shows as a connected service in the service map.
- [x] Trialled on a real Flutter repo; Dart syntax the grammar cannot read is listed as a follow-up.
- [x] Exact links from Dart's own indexer are out of scope (separate task).

## Outcome

Flutter apps now get the same code view as the other languages. Dart files index (symbols, outline, find, uses, deps) with imports and pubspec packages resolved; dio and package:http calls link to the backend endpoints they hit, controllers and minimal APIs alike; go_router routes link to their screens and literal navigation calls to routes. Trialled on fleetwise (mobile and hard-collection-app against the C# backend): 37 of 37 dio calls link to one endpoint each, 17 of 17 routes link to screens, 15 of 15 literal navigation calls link, no edge between the two apps. Syntax the grammar cannot read (macros, import augment) is filed as CS-126; helper navigation CS-124, extraction warnings CS-125, cross-app route hits CS-128, exact links from scip-dart CS-127 (later).
