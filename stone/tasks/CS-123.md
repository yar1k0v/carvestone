## Description

Part of CS-99. GoRoute(path: '/cases/:id', builder or pageBuilder => SomeScreen(...)), nested and relative child routes, named routes and ShellRoute/StatefulShellRoute become inferred route-to-screen links, and context.go/push calls with a literal path link the calling code to the same route, so stone code uses on a route path lists the screen that opens and the code that navigates to it. See batch B4 in .planning/v1/m14.md.

## Acceptance criteria

- [ ] GoRoute(path: '/map/:vehicleId', builder: (c, s) => MapScreen(...)) gives a route /map/:vehicleId with an inferred link to MapScreen, for expression builders, block builders that return the screen, and pageBuilder with MaterialPage, NoTransitionPage or CustomTransitionPage child.
- [ ] A child GoRoute with a relative path ('commands') joins its parent's path (/map/:vehicleId/commands); an absolute child path stands alone.
- [ ] ShellRoute, StatefulShellRoute and StatefulShellBranch pass their children through without adding a path; the shell's own builder is not linked as a screen.
- [ ] A route with name: 'x' is also found by context.goNamed('x') / pushNamed('x').
- [ ] context.go / push / pushReplacement / replace with a literal or interpolated path ('/map/${v.id}') links the calling code to the matching route of the same Flutter project; a variable path links nothing.
- [ ] stone code uses on a route path lists the screen and the navigating code; a route whose builder shows no screen, or a path held in a constant, links nothing and raises no error.
- [ ] Links are inferred, a refresh equals a rebuild, and two Flutter projects with the same routes never link to each other.

## Outcome

B4 done, left in-progress for B5. New crates/graph/src/fw_dart_router.rs reads go_router from each Dart file: GoRoute(path, name, builder or pageBuilder), nested relative and absolute children, ShellRoute / StatefulShellRoute / StatefulShellBranch passed through (their builder is no screen), and context/router go, push, pushReplacement, replace (literal or interpolated path starting with /) and goNamed, pushNamed, pushReplacementNamed, replaceNamed. Sites are RefKind::Opens in FileFacts::frames, told apart by qualifier (route or route:<Screen>, as:<name>, go, named); every route is also a DeclKind::Route declaration named by its full path with qname route:<path>, added after the sites' scopes are computed (dart.rs appends to frames, it does not overwrite). Edges are made in framework.rs screen_edges, inferred only: the screen type has a handles edge to the route (so uses <route path> lists the screen), code that navigates has an opens edge to it; a literal segment beats a parameter, :name and {} are parameters, a nav path of only parameters links nothing. Matching is inside the nearest pubspec folder only (files outside any pubspec form one group); a screen class is looked up in the router's own file, then its project, then path-dependency projects, never elsewhere. A constant or variable path, a builder with no capitalised constructor, test files and unmatched calls link nothing and raise no error. New kinds: RefKind::Opens (facts.rs, FRAMEWORK_EDGE_KINDS_SQL, kept_guess in index schema.rs, arms in all resolve_*.rs), DeclKind::Route (stored kind route; find --kind route, code_short, path:line and native symbol queries leave routes out like topics). CODE_GRAPH_VERSION 11. Known limit: two apps with the same route path share the symbol name route:<path>, so uses /cases/:id lists both apps' screens and callers together; each edge itself stays inside its app (deps of a screen or caller shows its own app's router). Tests: graph dart_router (16), engine code_framework (3 new: uses and deps of a route, two apps apart, edits equal a rebuild).
