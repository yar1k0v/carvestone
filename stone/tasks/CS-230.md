## Description

An empty answer from `stone code find`, `outline`, `uses`, `deps`, `impact` or `path` now carries three more lines: what Stone indexes for the language of the target, what it never indexes (string literals, config keys), and the grep command to run next. The engine builds the text once, so the CLI, the MCP `code` tool and the server JSON all carry it in a new `gap` field. For agents and people who read "nothing uses X" as a fact (ADR-21).

## Plan

Where an empty answer is printed today, all in `crates/cli/src/main.rs`: `#linked_or_none` ("nothing uses X", "X depends on nothing"), `#render_code` ("no matches for"), `#render_outline` ("declares nothing"), `#render_impact` ("nothing depends on") and `#render_path` ("no path between"). `--json`, the MCP tool `crates/mcp/src/tools.rs#code_tool` and the server route `crates/server/src/routes.rs#code_op` serialize the engine structs as they are, so the text must sit in the structs. `code explain`, `code entries` and `code native` answer about components and indexers, not about one symbol: they stay as they are.

The shared wording, three lines joined with `\n`, no newline at the end:

- Line 1, one of:
  - target with a language: `indexed for <lang>: declarations, and these links between them: <kinds>`, where `<kinds>` is the edge kinds stored for that language, sorted and joined with `, `. With no edge stored: `indexed for <lang>: declarations only, no links between them yet`.
  - target file with no language: `indexed for this file: nothing, Stone does not parse this file type`.
  - no target (`find`): `indexed here: declarations of <langs>`, the languages of the indexed files, sorted and joined with `, `. With none: `indexed here: no code`.
- Line 2, always: `not indexed: string literals, config keys`
- Line 3: `next: git grep -n -F -e "<term>"`, with one more ` -e "<term>"` for each further term.

1. New file `crates/engine/src/code_gap.rs` (new), and `mod code_gap;` in `crates/engine/src/lib.rs` beside `mod check_links;`. It holds:
   - `pub(crate) enum Asked<'a> { Lang(&'a str), UnparsedFile, Store }`.
   - `pub(crate) fn gap(conn: &rusqlite::Connection, asked: Asked, terms: &[&str]) -> Result<String, EngineError>` (`crates/engine/src/repo.rs#EngineError`). Kinds: `SELECT DISTINCT e.kind FROM edge_ends e JOIN files f ON f.id = e.file_id WHERE f.lang = ?1 ORDER BY e.kind`. Languages: `SELECT DISTINCT lang FROM files WHERE lang IS NOT NULL ORDER BY lang`. A term loses every `"` before it is printed.
   - `pub(crate) fn term(label: &str, is_file: bool) -> &str`: for a file, the text after the last `/` and before the last `.` of that text; else the text after the last `::` or `.`, whichever comes later.
   - `pub(crate) fn of_target(conn, target: &Target) -> Result<String, EngineError>` (`crates/engine/src/code.rs#Target`): the language is `SELECT lang FROM files WHERE id = ?1` for `target.file_id`, else `SELECT f.lang FROM symbols s JOIN files f ON f.id = s.file_id WHERE s.id = ?1` for `target.ids[0]`. A NULL or no row gives `Asked::UnparsedFile`. It calls `gap` with `term(&target.label, target.file_id.is_some())`.
   Seam: catches every wording difference between commands, since no other code builds these lines. Misses nothing a test needs: the functions are private and step 7 reaches them through the public API. Test choice: none here.
2. `crates/engine/src/code.rs#CodeResult` and `#Outline`, `crates/engine/src/code_graph.rs#Impact` and `#PathResult`: add `pub gap: Option<String>` after `note`, with the same two attributes `note` has and the doc comment `/// Set only on an empty answer: what is indexed, what is not, and the grep command to run next.` Set `gap: None` in every place that builds these structs (the compiler lists them).
3. `crates/engine/src/code.rs#edge_query`: keep `target.label` in the result as today, and after `result(...)` set `gap` to `Some(code_gap::of_target(conn, &target)?)` when `hits` is empty. Compute it before `target.label` moves into `result`.
4. `crates/engine/src/code.rs#find`: when `found.hits` is empty, set `gap` to `Some(code_gap::gap(conn, Asked::Store, &[text])?)`. The `NO_ROOTS_NOTE` branch stays, so that answer has both `note` and `gap`.
5. `crates/engine/src/code.rs#outline`: when `entries` is empty, set `gap` from `code_gap::of_target`.
6. `crates/engine/src/code_graph.rs#impact`: when `dependents` is empty, set `gap` from `code_gap::of_target`. `#path`, in the `let Some(..) = walked else` branch only: language of `a` as in `of_target`, terms `[term(a), term(b)]`; add `pub(crate) fn of_targets(conn, a: &Target, b: &Target)` to `code_gap.rs` for it, and let `of_target` share its code.
7. Test, in `crates/engine/tests/features/code_graph.rs`. Choice: add one table test `an_empty_answer_says_what_is_not_indexed`, because `gap` is new public behavior and no existing test reads an empty answer of every command. Fixture `#rust_project`. Rows (command, target, last line): `uses` of `total` → `next: git grep -n -F -e "total"`; `deps` of `total` → the same; `impact` of `total` → the same; `outline` is left out (the fixture has no empty file); `path` from `total` to `helper` → `next: git grep -n -F -e "total" -e "helper"`; `find` of `zzz` → `next: git grep -n -F -e "zzz"`. Then one assert that a filled answer has no gap: `uses` of `helper` gives `gap == None`. Red first: add the field in step 2 with `None` everywhere, run the test, and see it fail on the assertion.

Print it right after the headline and before `code_tail` in the five empty branches named at the top (`#linked_or_none`, `#render_code`, `#render_outline`, `#render_impact` after the headline and before `{tail}`, `#render_path`).
