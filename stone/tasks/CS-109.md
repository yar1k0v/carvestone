## Description

stone task move <id> done refuses when the task has no plan or no outcome section and says which one is missing. From the Freightline zoom-in trials: an agent skipped the plan and went straight to editing.

## Acceptance criteria

## Outcome

A store can require a plan before done: done_needs_plan: true in stone/config.yml, or stone init --require-plan, makes stone task move <id> done and stone edit --set status=done refuse a task without a filled ## Plan or ## Outcome, naming what is missing and the stone edit command that adds it. Off by default; an outcome was already required for done everywhere. stone check does not flag done tasks that lack a plan, so turning it on does not light up old tasks.
