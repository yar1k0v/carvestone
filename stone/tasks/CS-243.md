## Plan

Before step 1: `target/debug/stone.exe map` must print the project map (CS-231). If not, stop and report.

`stone init` refuses a store that exists (`crates/engine/src/create.rs#init_with`), so the offer at init alone never reaches an existing project. `stone map --install-hook` adds the same hook later, as `stone commit-msg --install-hook` does for the commit hook.

The hook, as Claude Code reads it from `.claude/settings.json`; what a SessionStart command prints goes into the context of the session:

```json
{
  "hooks": {
    "SessionStart": [
      { "hooks": [{ "type": "command", "command": "stone map" }] }
    ]
  }
}
```

1. `crates/engine/tests/features/workspace.rs`: add the table test `the_session_hook_is_added_once_and_keeps_the_settings`. Test choice: add, because it writes a file format that the user owns. Add `pub mod session_hook;` to `crates/engine/src/lib.rs` and the items of step 2, with `apply` returning its input, so the test fails on its assertions. Rows, each a text given to `session_hook::apply` and the expected result:
   - An empty text → exactly the JSON above, with two-space indent and a final newline.
   - `{"permissions":{"allow":["Bash(ls)"]},"env":{"A":"1"}}` → the keys stay in the order `permissions`, `env`, then `hooks`, and both old values are unchanged.
   - A text that holds another `SessionStart` entry → that entry stays first, and the stone entry is added after it.
   - The result of the first row, given again → the same text, byte for byte.
   - A text whose hook command is `target/debug/stone.exe map` → the same text (a repository that runs its own build keeps its command).
   - `[1]` and `{"hooks": 3}` → `Err`.
   - It catches lost or reordered user settings and a hook added twice. It misses whether Claude Code runs the hook, which a new session shows.
2. New file `crates/engine/src/session_hook.rs`:
   - `pub const SETTINGS: &str = ".claude/settings.json";` and `pub const COMMAND: &str = "stone map";`

Return `text` unchanged when some `hooks.SessionStart[].hooks[].command`, trimmed, ends with `stone map` or `stone.exe map`. Else push `{ "hooks": [{ "type": "command", "command": COMMAND }] }` onto `hooks.SessionStart`, creating the two keys when missing, and return `serde_json::to_string_pretty` plus `\n`.
   - `pub struct SessionHook { pub file: String, pub changed: bool }`, where `file` is `SETTINGS`.

An `apply` error becomes ``EngineError::Invalid(".claude/settings.json: {why}; nothing was written. Add a SessionStart hook with the command `stone map` by hand")``.
