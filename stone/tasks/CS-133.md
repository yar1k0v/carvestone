## Description

From the Fleetwise session. stone instructions prints text compiled into the binary, written for Carvestone (CS-n ids, cargo lines). Each project should teach agents its own workflow: the guide is read from an item in the store being used (a doc or config item), with the built-in text as the fallback. A project can replace one topic (overview, plan, do, finish) and keep the others. Fleetwise's replacement text is in its task AC-171, section instructions-fix, and its agent protocol in doc docs/lld-agent-protocol (read with stone get in that store). Size: medium. Open for the product owner: which item type holds the guide, and whether stone check validates that the commands a project guide names exist.

## Acceptance criteria

- [x] With docs/instructions in the store, stone instructions [topic] prints that section; a missing section or doc prints the built-in text
- [x] A project can replace one topic and keep the rest
- [x] stone check reports a project guide that names a stone command stone does not have
- [x] The built-in guide stays for Carvestone
- [x] cargo test --workspace and cargo clippy --workspace --all-targets -- -D warnings

## Decision

Decided by the product owner 2026-10-31: the project's guide is one doc, docs/instructions, with one section per topic named overview, plan, do and finish. A section present in the doc replaces the built-in text of that topic; a missing section falls back to the built-in text; without the doc, all four are built in.

## Outcome

stone instructions now reads the item docs/instructions of the store in use. A section headed overview, plan, do or finish (any letter case, nested headings included) replaces that topic; a topic without a section, a store without the doc, and a directory outside any store all print the built-in text, so Carvestone keeps its own guide and nothing fails. stone instructions --write is unchanged. stone check reads the doc too and warns (rule guide) about a backticked stone command or subcommand stone does not have, a heading that is not one of the four topics, and a topic written twice. The overview has one line saying a project can replace a topic.
