## Description

A contributor who runs `stone init`, or `stone config merge-driver` in a repo that is already set up, gets the stone merge driver: `.gitattributes` routes `stone/**/*.md` to it and git config names the binary.

## Acceptance criteria

- [x] `bash scripts/check.sh ws cargo test -p carvestone-engine --test features workspace::init_inside_a_repo` → 1 passed
- [x] `bash scripts/check.sh cli-build cargo build --bin stone` → exit 0
- [x] `target/debug/stone config merge-driver` → prints the `.gitattributes` line and the driver command
- [x] `git config --get merge.stone.driver` → ends with `merge-file %O %A %B %P`
- [x] `git grep -n "merge=stone" -- .gitattributes` → 1 match

## Plan

1. `crates/git/src/work.rs#Git::set_config` (new): `pub fn set_config(&self, key: &str, value: &str) -> Result<(), GitError>`, runs `git config <key> <value>` through `Git::exec`. Test: none (wiring, covered by step 5).
2. `crates/engine/src/create.rs#ignore_lines` becomes `append_lines(path: &Path, wanted: &[&str]) -> Result<Vec<String>, StoreError>` with the same body, the file path as an argument. `init_with` calls it with `root.join(".gitignore")`. Test: none (refactor, existing init test stays green).
3. `crates/engine/src/create.rs#install_merge_driver` (new): `pub fn install_merge_driver(root: &Path) -> Result<MergeDriver, EngineError>`, `pub struct MergeDriver { pub attributes_added: bool, pub command: String }` (new). It calls `append_lines(&root.join(".gitattributes"), &["stone/**/*.md merge=stone"])`, then `Git::set_config("merge.stone.name", "stone item merge")` and `Git::set_config("merge.stone.driver", command)`. `command` is `"<exe>" merge-file %O %A %B %P`, where `<exe>` is `std::env::current_exe()` with `\` replaced by `/`, in double quotes. Running it twice changes nothing the second time.
4. `crates/engine/src/create.rs#init_with`: when `in_repo`, call `install_merge_driver` after `ignore_lines`. Add `pub merge_driver: Option<MergeDriver>` to `Initialised`. `crates/cli/src/main.rs` init output prints `merge driver: <command>` when set.
5. `crates/cli/src/main.rs#ConfigCommand::MergeDriver` (new): `stone config merge-driver` calls `install_merge_driver` on the repo root and prints `.gitattributes: stone/**/*.md merge=stone` (`added` or `present`) and `driver: <command>`. Refuses with a plain sentence when the root is not in a git repo.
6. Test: patch `crates/engine/tests/features/workspace.rs#init_inside_a_repo_indexes_the_whole_repo`. Assert `.gitattributes` holds the line `stone/**/*.md merge=stone`, `git config --get merge.stone.driver` in the fixture repo ends with `merge-file %O %A %B %P`, and a second `install_merge_driver` returns `attributes_added == false`. Catches: a missing line, a wrong command, a duplicate line. Misses: git actually calling the driver (CS-272 covers the merge logic).

## Outcome

stone init and stone config merge-driver now add 'stone/**/*.md merge=stone' to .gitattributes and set merge.stone.driver in git config. Checked: workspace init test 1 passed, stone build exit 0, config merge-driver run here, git config and git grep show the driver and 1 match.
