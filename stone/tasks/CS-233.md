The gaps, in this order, each one plain sentence. `{id}` is the task label, for example `CS-7`:

| Check | Gap sentence |
|---|---|
| `components` is empty | ``components is empty; set it with `stone edit {id} --set components=<arch id>` `` |
| `paths` is empty | ``paths is empty; set it with `stone edit {id} --set paths=<file>,<file>` `` |
| a `paths` entry is not on disk and is not marked | ``path {p} does not exist; fix it in paths, or write it in the plan as a code span followed by (new)`` |
| no checkbox under Acceptance criteria | ``no acceptance criterion; add `- [ ]` lines under ## Acceptance criteria`` |
| checkbox n has no code span | ``criterion {n} carries no command; put the command in a code span`` |
| no Plan section, or no line in it that starts with digits, a dot and a space | ``the plan has no numbered steps; write them under ## Plan`` |
| a plan target names a file the graph does not hold | ``plan line {line}: {target} names a file the code graph does not hold; fix the path or mark it (new)`` |
| a plan target names a symbol that is not in its file | ``plan line {line}: {target} names a symbol that is not in that file; fix the name or mark it (new)`` |

Rules for plan targets: only the Plan section is read, fenced lines are skipped. A target is a code span that `crates/engine/src/design.rs#span_target` accepts (a path with an extension, `#`, a symbol, no spaces); a span that starts with `#` is not a target. A span is marked when the text right after its closing backtick, spaces skipped, starts with `(new)`. A marked span is not checked. One mark covers every later use: an unmarked target is skipped when the same span text, or a span of only its path part, is marked anywhere in the plan. A file that is on disk but not in the code graph (a doc, a manifest) is not judged, as in `crates/engine/src/design.rs#flow_problems`. When `crates/engine/src/code_entries.rs#has_code` is false, no target is judged.
