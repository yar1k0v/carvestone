## Description

With a real scip-go index, code uses names the file, not the calling function, because Stone reads only the deprecated end-line field. After this task it names the function.

## Acceptance criteria

- [x] `cargo test -p carvestone-engine --test features code_graph::` → exits 0, `0 failed`, and the new assertion passes
- [x] `cargo clippy --workspace --all-targets -- -D warnings` → exits 0
- [x] `target/debug/stone.exe code uses Greet --root <trial folder>` → prints `run` as the caller, not the file

## Plan

Proven cause: `enclosing_end` in `crates/graph/src/scip_read.rs` reads only the deprecated `enclosing_range`. scip-go 0.2.9 writes `typed_enclosing_range`, so a function gets a one-line range, and a reference in its body lands on the file. Keep no next-definition fallback: no indexer is known to need it.

1. In `crates/graph/src/scip_read.rs#enclosing_end`, read `typed_enclosing_range` first, then the deprecated `enclosing_range`.
2. Check the line reader beside it the same way: an occurrence with only `typed_range` must keep its line. Change it only if it ignores that field, and say so under `## Notes`.
3. Test choice: patch. In `crates/engine/tests/features/code_graph.rs`, add to the SCIP-only test a file whose definitions use `typed_enclosing_range` only, with two functions and a call inside the second. Assert that `uses` names the second function as the caller, and not the file. It catches a reference that lands on the file. Keep the existing case for the deprecated field.
4. Run `cargo build --bin stone`, then the acceptance commands.
5. Rerun `code native` and `code uses Greet` with `--root` on the trial folder, and paste the output under `## Notes`.
