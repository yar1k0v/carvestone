## Description

For a language listed in scip_indexes, the SCIP pass creates symbols from the index's definitions, with kind, name and lines, so find, outline, uses and impact work. A test with a hand-built index proves it. Runs after CS-193.

## Plan

A file is SCIP-only when `files.lang` is a language from `scip_indexes` and not a built-in `Lang`. Its symbols have no signature or doc in this version. A changed file has no symbols until the next `stone code native`, and the existing out-of-date note covers that.

1. In `crates/graph/src/scip_read.rs`, add `end_line: Option<u32>` to `ScipOccurrence`, read from the occurrence's `enclosing_range` (0-based, last line).
2. In the same file, add `pub struct ScipSymbol { qname: String, name: String, kind: &'static str, parent: Option<String> }` and `pub fn scip_symbol(symbol: &str) -> Option<ScipSymbol>`, using `scip::symbol::parse_symbol`. Never parse the string by hand. `qname` is the descriptor names joined with `.`. `name` is the last descriptor's name. `parent` is the qname without the last descriptor. `kind` comes from the last descriptor's suffix: Namespace or Package `module`, Type `type`, Term `member`, Method `method`, or `function` when no Type descriptor comes before it. Any other suffix gives `None`. Export both from `crates/graph/src/lib.rs`.
3. Test choice: add. New parsing logic with real branches. Create `crates/graph/tests/scip.rs`, one table test of `scip_symbol`, with expected values written by hand from the SCIP symbol grammar: a Java class, a Java method, a Go top-level function, a Go package, a local symbol (`None`), an invalid string (`None`).
4. In `crates/engine/src/code_native.rs`, add `create_symbols`, called at the start of `ingest` in its own transaction, the same way `store` opens one. For each document of a SCIP-only file: take the definition occurrences that `scip_symbol` accepts, and insert one `symbols` row each with `file_id`, `qname`, `name`, `kind`, `line_start`, `line_end` (`end_line`, else the same line) and `lang`. Set `parent_id` when another symbol of the same file has `parent` as its `qname`. Add each row to `symbols_fts` the way `insert_code` does.
5. Before inserting, remove the file's symbols other than `file`, the same way and in the same order as the function in `crates/engine/src/code_index.rs` that holds `DELETE FROM symbols_fts WHERE rowid IN`. A second pass on the same index must give the same rows. If foreign keys block the delete, stop and report under `## Notes`.
6. The rest of `ingest` then finds these rows through `load_decls` and `declared`, and writes edges as usual. Change nothing there.
7. Test choice: add. New public behavior. In `crates/engine/tests/features/code_graph.rs`, build an `Index` with the `scip` types, write it with `write_to_bytes`, and list it in `scip_indexes`, using two `.java` files where one calls the other. Assert through the public API: `find` gives the class and method, `outline` lists them nested, `uses` gives the caller, and a second `native` pass gives no duplicate. Add `scip` and `protobuf` to `[dev-dependencies]` of `crates/engine/Cargo.toml`, at the versions `crates/graph` uses.
8. Run `cargo build --bin stone`, then the acceptance commands. Install no outside tool in this task. The trial on a real indexer is its own task, after the owner decides how to run it.

## Notes

Step 6 ruled by the Lead: create_symbols also writes refs rows (kind references, src = innermost definition holding the line, NULL when none, which ingest reads as the file symbol); lang_from made pub(crate) in code_index.rs; a file whose symbols and sites already match is skipped, so a repeat pass leaves graph_version unchanged. SCIP cannot tell a call from a plain name use, so every site is references. Review gap closed: the engine test now runs a changed index (call added, call removed, method removed) and checks uses, find, search, outline and graph_version after each. Breaking the site comparison in the skip, and the symbols_fts delete, each made it fail. A removed site alone is invisible to uses (an edge needs the index occurrence too), so the site comparison is proven by the added-call step.
