## Plan

Owner decisions (2026-11-08): semantic versions starting at 0.1.0 (the current `[workspace.package] version`). A build script bumps the version on request and builds the release binary with the UI into `build/`. `stone --version` names the commit, so every build can be traced.

1. In `crates/cli/build.rs#main`, before the Windows-only return, set `STONE_BUILD` for the crate: run `git rev-parse --short=7 HEAD` in `CARGO_MANIFEST_DIR`. If it succeeds, the value is `+<hash>`, and `+<hash>.dirty` when `git status --porcelain --untracked-files=no` prints anything. If git fails or is missing, the value is empty, so a build from a source archive still works. Print `cargo:rustc-env=STONE_BUILD=<value>`, and `cargo:rerun-if-changed` for `../../.git/HEAD` and `../../.git/index` when they exist. Never panic on a git failure.
2. In `crates/cli/src/main.rs#Cli`, replace the bare `version` attribute with `version = concat!(env!("CARGO_PKG_VERSION"), env!("STONE_BUILD"))`, so `stone --version` prints `stone 0.1.0+94b3df6`.
3. Add `scripts/build.sh` (bash; it runs in Git Bash on Windows and on Linux and macOS). Usage: `scripts/build.sh [patch|minor|major]`.
   - With an argument: read `version = "X.Y.Z"` under `[workspace.package]` in `Cargo.toml`, bump the part (minor resets patch, major resets minor and patch), and write it back changing only that line. Print `version X.Y.Z -> A.B.C`. Any other argument: print the usage and exit 1.
   - Then: `pnpm --dir web build`, `cargo build --release --features ui --bin stone --target-dir target/build-release`, and copy the binary (`stone.exe` on Windows, else `stone`) to `build/`. The separate target folder means a running `target/release/stone.exe` never blocks the build.
   - Last: print the copied binary's `--version`. Stop on the first failing step (`set -euo pipefail`).
   - It never commits, tags or pushes. A bump leaves `Cargo.toml` and `Cargo.lock` changed for the owner to commit.
4. In `.github/workflows/release.yml`, first step of the `build` job after checkout: fail when the tag without its `v` differs from the `Cargo.toml` workspace version, with a message naming both.
5. In `README.md`, add a short `Releases` part under Install: `scripts/build.sh [patch|minor|major]`, what `--version` prints, and that a release is a tag `v<version>` pushed after the bump is committed.
6. Test choice: none. Build wiring and a script; the acceptance commands run them.
7. Run the acceptance commands. Do not run a bump on this repo's `Cargo.toml` except the one in the criteria, then restore it with `git checkout -- Cargo.toml Cargo.lock`.

The release workflow rejects a tag that differs from Cargo.toml. Checked by running the script (plain, minor, wrong argument), fmt, clippy and the workspace tests.
