## Description

`stone config` can add `code_roots` and `scip_indexes` (CS-212) but not `doc_roots`. A store that reads docs from another repo (VibeHunt keeps specs and decisions in its `docs/` GitHub repo and points `doc_roots` at it) must edit `stone/config.yml` by hand, which the stone-guard hook and the `Edit(/stone/**)` deny block. Add `stone config add-doc-root <folder> [--dry-run]`, the same shape as `add-code-root`: one list entry, comments and other lines kept, a folder already listed changes nothing.

## Acceptance criteria

- [x] `cargo test -p carvestone-engine --test features config_edit::` → all pass, `N passed` includes the new doc_roots rows (add, already listed, no `doc_roots` key yet, bad path)
- [x] `cargo build --bin stone` → exit 0
- [x] In a temp store: `target/debug/stone config add-doc-root docs/` → `stone/config.yml` gets `doc_roots:` with `- docs/`, other lines and comments unchanged; a second run prints no change
- [x] `target/debug/stone config add-doc-root docs/ --dry-run` → prints the change, writes nothing
- [x] `target/debug/stone config --help` lists `add-doc-root`

2. Add `Repo::add_doc_root(&self, path: &str, dry_run: bool) -> Result<Written, EngineError>` (new) after `Repo::add_code_root`, the same shape. Trim the path. Inside `edit_config`: parse the old text with `Config::parse`; normalize the path as `path.replace('\', "/")`, then strip leading `./` and trailing `/`; if `config.doc_folders()` (`crates/store/src/config.rs#Config::doc_folders`) holds that folder, return `Ok(None)`. Otherwise `add_entry(old, &config, Entry::Doc(path)).map(Some)`. Write the path as given (`docs/` stays `docs/`). Add no path check of its own: `finish` re-parses the text, and `Config::parse` refuses an empty root, `..`, `.`, a drive and `stone/` with its `invalid \`doc_roots\` entry` message, before anything is saved.
